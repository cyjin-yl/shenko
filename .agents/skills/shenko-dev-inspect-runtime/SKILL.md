# 观察当前运行

先读 [shenko-dev 根哲学](../shenko-dev/SKILL.md)；已读且未变化时复用理解。
可以直接观察，不必先建立任务清单、填写表格或运行其他技能。

## 目标

取得足以回答当前问题的现场事实，并能区分它们与设计承诺。

## 选择观察方式

- 找到相关的实际实例、版本、provider 绑定和节点身份；名称相同不代表对象相同。
- 使用已有接口、日志、状态读取、界面，以及可达机器、网络与可发现的服务；不必局限于已知清单，选最直接的路径。
- 遇到观察不到的阻塞先穷尽可达资源：本机 root、已授权 SSH 节点、可达网络与可发现的服务都可能提供新的运行事实；把新发现记录为现场事实，而不是提前宣布无法观察。
- 可以主动拉取观察，不必等待 webhook、报错或用户再次发消息。
- 把文档所述、已安装、已启用、实际可用和本次已观察分开表达。
- 给观察保留必要的时间、revision 或来源，使过期材料能被识别。
- 查询只覆盖当前疑问；不要为一个连接问题扫描全部账户或机器。

## 解释真实边界

连接失败、没有回执和远端已停止是不同事实；不知道时保留未知。
核对当前主节点与相关节点状态，不能把单个进程存活当作整个分布式系统健康。
已有 SSH、网络和操作系统权限按根哲学使用；观察不能凭文档虚构屏幕或执行能力。
需要会改变状态的探针时，按具体已授权动作处理并记录效果，不伪装成被动读取。
秘密使用凭据设施或 handle，诊断输出保留必要的非秘密标识。

## 足够的结果

提供与当前问题直接相关的观察、来源和结论范围即可；已有日志不必另抄一份。
发现异常可自主继续诊断或修复，也可把准确事实交给正在进行的开发。
观察正常就停止扩展检查；未取得现场证据时不要把设计写成运行结论。
