# 多设备、分区与无模型恢复

这些是同一自我的连续性与实际行动能力。当前产品合同见仓库 `SPEC.md` §§5.4、10–11、22、24、38、41 及本轮原话 U57、U60–U62。实现应复用现有持久事实、身份、节点和执行协议，不为每项说明另建一个平台。

## 区分自我、主节点与能力

| 对象 | 要保留的含义 |
| --- | --- |
| 自我/身份 | 经历、关系、人格、承诺与目标的持续归属 |
| 节点 | 一台真实设备或执行环境，有本地资源和授权 |
| 当前主节点 | 在当前连通域拥有主体决策序列与协调职责的节点 |
| Provider/模型访问 | 某节点此刻可用的本地或远程服务及真实能力 |
| 子 Agent | 由主体安排、可在不同节点和模型上执行的有限工作 |

较早创建的身份不必永久占据主节点；最新选出的主节点也不必创建新人格。把身份创建事实与选主代际分别记录，不拿机器墙钟较小或网络广播里的自述单独证明谁更早、更可信。

## 新身份加入已有自我

新部署节点先发现可达节点，依据已授权的节点身份/SSH 信任关系确认更早的自我及所属主节点，然后撤销自己的独立活动身份，从同步该身份开始加入。旧临时身份不继续争夺主体地位；后续状态、任务和能力都按新的归属接续。

“毁掉当前身份”作用于活动身份和独立主体资格。它不是删除设备文件、抹去已经执行的外部效果或复制所有凭据的同义词。若初始化期间已经产生事实，保留准确来源与收据，在新归属下可查。不能因为网络里任意机器声称更早，就接受其身份替换。

已经属于同一自我、因分区而各自生活的节点重连时，要合并分支经历与未竟工作；不能把有历史的分支当空白新节点重置。不同已建立自我的冲突也不能靠伪造创建时间掩盖。

## 网络通路与操作能力

主要接入方式是已授权给 Shenko 的 SSH Key。内网直接发现/探测、Tailnet、ZeroTier 等可以帮助找到、连接和观察节点；它们不必成为核心常驻依赖。SSH 也不是所有操作的唯一传输，具体屏幕、应用或运行时能力可以采用适用的 provider。

在真实授权范围内暴露完整节点能力：root Android 可以提供屏幕控制与任意 Shell，Linux/macOS/Windows 可提供相应文件、进程、窗口、桌面和应用操作。主体知道能力在哪个节点、以什么身份执行、目前是否可用，并委派实际工作。对已授权可用能力不额外设计逐操作的人类 gate。

若缺屏幕服务、桌面会话、OS 权限或工具，先如实感知并自主补足已允许的条件。不能只因为连上 SSH 就声称能操控一块尚不存在的屏幕。

## 模型与 provider 不必同步

节点可以各自运行不同本地 LLM，也可以独立访问 API；部分 provider 绑定、进程、句柄或凭据无法复制。同步自我只要求它们能按真实合同协作，不要求所有节点都拥有相同模型、相同配置或相同凭据。

主节点发现各节点当前的模型访问、上下文/工具支持、可用资源与执行环境，据此分派不同子 Agent。Android 加可用 Kimi-Code API 就可以有智能能力；Qwen3.8-27B 是已有参考部署，不是智能节点定义。

主节点断开时，由它承载且已不可达的模型通路不能继续计为可用。独立 API 或另一节点上的模型仍应按真实可达性判断；不要简单把所有同名模型一同置为可用或不可用。凭据是否可重新配置由既有授权和可用秘密存储决定，不由身份同步假装解决。

## 递归选主与分叉合并

正常连通时一个主节点协调持续主体。失去当前主节点或必要智能通路时，在当前可达且仍能访问 LLM 的候选中选择最聪明、实际能够接续工作的备用。依据已知模型能力与实际表现判断“聪明”，不只比较设备名称、CPU 或参数量；隐私约束和模型可用性也必须真实成立。

后续断连重复同一原则。完全分隔时，每个仍有 LLM 访问能力的节点可以成为独立节点，继续形成经历、目标和判断。这里选择在线优先，并承认暂时不同分支；不能同时宣称从未分叉。

重连时确定当前主节点，汇合原始事件与记忆、识别冲突并对账任务和外部效果。旧主的旧代际不能继续改写已经重新归属的工作。区分共同祖先、各自新经历、互相矛盾的判断和重复投递，保留实际来源；合并不是最后到达的摘要覆盖其他分支。

对已经发出的邮件、命令、迁移或部署保留收据、执行身份与未知结果。主节点切换或合并不能自动重放一遍。由原有可靠执行底座支持这一点，不为每个 awareness 添加一次分布式事务。

真正拒绝旧所有者的效果需要相应资源端支持。无法控制或不支持 fencing 的外部系统按实际收据和未知结果处理，不能仅凭新的主节点编号宣称旧操作已被阻止。迟到结果仍是应入账的事实，不恢复旧节点的决策权。

## 察觉供应商隐私

让节点说明实际使用的 provider、模型调用去向、传输和代理路径，以及当前已知的数据留存/训练使用/访问条件。把这些信息的来源、有效时间和未知项与能力描述一起提供；不能因为 API 从自己手机发出，就称其内容留在本地。

主主体根据当前目标、已有隐私约束和内容敏感性，自主选择节点/模型、减少交给该 provider 的材料、改用其他通路或补充核验。能力更强不自动意味着可以读取全部原始记忆；未知隐私也不等于已确认安全。无需另建逐次人工审批，真实授权及隐私约束继续有效。

如果节点只能访问不适用于当前材料的 provider，它仍有一般智能能力；不能因此把受限材料自动发送出去，也不必抹掉该节点所有其他用途。

## 所有 LLM 都坏掉以后

将系统日志、事件/记忆持久化、节点状态与凭据授权的导出做成不需要模型生成的实际功能。无可用 LLM 时，仍能在 OS、程序和存储可用范围内报告错误、记录事件、保留已有内容，并通过授权的外部工具提取。此时不声称主体仍在智能思考。

导出应能包含恢复所需的原始经历、附件引用及实际可用内容、记忆索引或重建入口、任务与效果记录、身份/分支来源、数据版本与完整性信息。派生摘要可以随附，但不能成为唯一可取的数据。使用原有存储和日志，不要求为了导出再跑一个 LLM。

如果运行环境也损坏，具备权限和必要解密凭据的操作者或其他节点应能复制磁盘镜像，离线定位并提取这些材料，再由有智能能力的节点理解、恢复、迁移或合并。恢复工具、格式说明与入口不能只藏在已失效模型的上下文中。

基于当前 SQLite WAL 与对象存储方案时，在线导出取得一致性读视图和来源水位，离线提取包括恢复所需的 WAL 与附件/对象；不能只拷一个数据库主文件就声称经历完整。将原始材料与可重建索引分清，记录实际可恢复范围。

磁盘镜像包含凭据或其他敏感材料时，按实际凭据与数据访问边界处理；无需为恢复发明新的身份，但也不能以“复活”名义绕开已有加密。没有写盘、已损坏或缺失密钥的材料如实标记缺口，不能让更强模型编造一份经历冒充原始事实。

这些可恢复能力可以随系统演进与替换；它们不是永久不可修改的内核区域。修改时保留能取回既有数据的实际路径。
