# 核对上游行为

先读 [shenko-dev 根哲学](../shenko-dev/SKILL.md)；已读且未变化时复用理解。
围绕实际需要核对，可独立使用；不要求每个改动重做全项目研究。

## 目标

确认相关版本究竟提供什么，以及 Shenko 需要采用、适配或自行实现什么。

## 取得直接证据

- 先明确要判断的行为，例如停止回执、状态恢复、接口参数或实际 UI 交互。
- 阅读对应版本的官方源码、协议、正式文档或发布记录；用直接证据解决不确定性。
- 区分发行版本、固定提交、主线和用户实际部署；新文档未必适用于旧构建。
- 源码与文档冲突时追到相关路径，必要时用一个针对性的实际观察判定。
- 没有当前证据就保留未知，不用模型记忆或搜索摘要替代精确合同。

## 决定采用边界

可以采用设计思想、接口的一部分或已有实现，不必机械复制上游全部产品。
写清 Shenko 增加的行为和真实差异；adapter 名称不能扩大后端保证。
变化影响现有用户行为时，自主选择兼容、迁移或替代方案并更新有关说明。
上游材料提供证据，不替代根哲学、当前用户意图或实际外部权限。
可与实现或诊断并行，只共享相关结论和可复查的来源。

## 足够的结果

留下适用版本、关键依据和采用判断即可；可直接写在代码说明、PR 或既有文档。
只有尚未解决的具体疑问值得继续查，不为了增加引用数量扩大调研。
需要进一步验证时选最直接的检查，遵守 [适量验证](../shenko-dev-verify/SKILL.md)。
证据足够后继续原任务，不等待逐项人类批准。
