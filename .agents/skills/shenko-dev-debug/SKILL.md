# 定位并修复根因

先读 [shenko-dev 根哲学](../shenko-dev/SKILL.md)；已读且未变化时复用理解。
按证据选择调查与修复路径，不要求先跑完整审计或填完检查清单。

## 目标

解释并修复这次真实失败，使原来的用户行为能够继续。

## 缩小实际原因

- 从具体症状、输入、版本和已有结果出发，先复用足够的现场证据。
- 选择能区分候选原因的最小观察、复现或代码追踪；结果改变判断就调整方法。
- 区分没有执行、执行失败、效果未知和仅投影错误，避免对未知外部动作盲重试。
- 找到相关原因后修复它；必要时改工具或方法，不以重复尝试代替理解。
- 对已授权自身环境中的漏洞，可以自主调查、修补、升级并检查原问题。
- 调查和修复只使用真实授权范围，不因 root、SSH 或网络可达而推断额外权限。

## 留住有用事实

保留失败证据与修复关系，不删除失败记录来制造通过结果。
复现困难时写明已观察条件和未确定部分，继续可做的修复或调查。
涉及其他并行工作的文件时协调归属，避免用大范围回退掩盖当前问题。
对无关的旧故障只保留简短线索；它不自动扩大此次修复范围。
测试只为具体疑问服务，遵守 [适量验证](../shenko-dev-verify/SKILL.md)。

## 足够的结果

症状、原因、改动和原问题的结果能够连成可复查的证据链即可。
优先复用同一条复现或现场观察确认修复，不为每个代码分支补一批镜像测试。
原因尚未确定时继续保留精确未知，不能把猜测包装成已修复。
修复后恢复原目标的推进，无需另等人工签字。
