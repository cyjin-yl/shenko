# 保存足够继续的事实

先读 [shenko-dev 根哲学](../shenko-dev/SKILL.md)；已读且未变化时复用理解。
按实际丢失风险保存，可以随时使用；不要求每轮写一份完整工作报告。

## 目标

让接手者能够从真实代码和现场继续原目标，避免重做已完成的外部动作。

## 选择需要保存的内容

- 标明工作目录、分支、commit、未提交修改及已有 PR；引用实际存在的对象。
- 保留最新用户决定、关键理由、已证明结果和真正未解决的问题。
- 记录仍在运行或状态未知的模型请求、远端任务、seat、进程及可查询 handle。
- 区分工作已提交、已推送、已部署和已观察，不能用一个“完成”标签覆盖它们。
- 给出下一件可以直接执行的工作和定位入口；已有计划足够时直接引用。
- 只保存必要的资源身份和凭据 handle，不把秘密复制到交接文档。

## 保持记录轻量且真实

优先更新现有接续位置，代码与工件进入当前任务允许的 Git 路径。
在已有授权内及时提交或推送；无法远端保存时明确本地状态和缺口。
继承现有有效授权和用户意图，不要求接手者逐项重新请示。
不要把之前会话的工具句柄假设为仍然可用；恢复时核验真实实例和外部状态。
记录可以很短，省略可从代码、Git 或既有证据直接重建的过程叙述。

## 足够的结果

接手者能找到成果、避免重复效果、理解未决事项并继续行动，即为足够。
给出精确保存位置和状态即可，不额外制作另一份全量副本。
完成 checkpoint 后按当前目标继续工作，或在明确的交接边界结束。
