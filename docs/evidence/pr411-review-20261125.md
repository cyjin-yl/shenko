## Why the delivered consumer boundary is narrower

The missing root-space observer is a real generated-support closure defect.
The positioning host imports and calls that module, but the compiler's
target-alignment emitter neither remaps the edge nor emits its neighbor.
Both fresh native-support generation and migration are affected; describing
it as migration-only would be incorrect.

The current consumer was inspected against its actual generated bytes:

- `web/compiler.mjs` calls `compileFile()` and `writeCompilation()`
  for two presentational, closed-source inputs using
  `react-dom-source-v1`. It does not call shared-support migration,
  library linking or project compilation.
- Both generations contain the component, map, provenance, React/scope
  context helpers and native-style support. Neither contains interaction,
  target-alignment or host-web support, nor an authored Transition.
- The 16 upstream families use public packages via
  `createReactAdapter()`; they do not use these defective generated-support
  or Brutalist compiler paths. Their actual production build and current App
  browser interactions are independently recorded above.

This supports admission of the **currently delivered consumer behavior**.
It does not validate unused compiler paths, all style-family scans or a future
family migration. Native-support closure repair, strict Transition typing,
budget-diagnostic alignment, Brutalist compile support and the observed style
timeouts remain upstream work before the corresponding features can be
claimed ready. No upstream source, assertion, timeout or CI requirement was
weakened to obtain this result.
