# 官方 QQ Bot 通道：可达动作与平台边界的逐项对照

日期：2026-11-10。对应 issue #251、SPEC §57.4 / §57.15、验收 RT19。

这份对照的每一条都来自腾讯开放平台的官方文档（页面与读取日期见每行）。
它回答两个问题：**插件宣称的动作，平台真的做得到吗？** 以及 **平台真实的边界是什么？**
边界按事实记录，不写成产品的权限门，也不因为"能发出去"就假装"一定发得出去"。

## 一、消息动作：文档里有的才有

| 动作 | 官方文档 | 插件的可达性 |
|---|---|---|
| 发送单聊消息 | `POST /v2/users/{user_openid}/messages`（发送单聊消息） | 可达 ✓（`send_private_message`） |
| 流式发送单聊消息 | `POST /v2/users/{user_openid}/stream_messages`（发送单聊消息） | 未实现（群场景不支持流式，单聊流式是独立端点）——能力表不宣称 |
| 发送群消息 | `POST /v2/groups/{group_openid}/messages`（发送群聊消息） | 可达 ✓（`send_group_message`） |
| 发送子频道消息 | `POST /channels/{channel_id}/messages`（发送子频道消息） | 可达 ✓（`send_channel_message`） |
| 撤回单聊消息 | `DELETE /v2/users/{user_openid}/messages/{message_id}`（撤回单聊消息） | 可达 ✓（`retract_message`） |
| 撤回群聊消息 | `DELETE /v2/groups/{group_openid}/messages/{message_id}`（撤回群聊消息） | 可达 ✓（`retract_message`） |
| **编辑消息** | **文档索引（接口文档索引）里没有任何消息编辑端点**：消息相关的端点只有发送、撤回、流式发送与媒体上传** | **不可达 → 能力表 `edit: false`，插件不提供 `qqo-edit` 这个回复种类** |
| 富媒体 | `POST /v2/groups/{group_openid}/files`、`POST /v2/users/{user_openid}/files`（富媒体） | 可达 ✓（先上传拿 `file_info`，再以 `msg_type: 7` 发送） |
| 打字指示 | 文档未在消息动作里列出；QQ 频道另有独立端点 | 不可达 → 能力表 `typing: false`（一次回复就是一个效果） |

**这一轮改掉的**：官方 QQ 适配器此前宣称 `edit` 可达，实际调用的是 `PUT /v2/messages/{message_id}` —— 这个端点不在官方接口索引里。按 RT19（能力表只列 `describe` 实际能产出的动作），编辑动作、它的合同摘要与 API 客户端方法都已删除；收到编辑派发时按平台事实拒绝，而不是改写成一次重发。

飞书对照：飞书确实有 `PATCH /im/v1/messages/{message_id}`（编辑消息），因此飞书适配器的 `edit` 保留 ✓。

## 二、平台边界（按事实记录）

| 边界 | 官方文档 | 插件里的体现 |
|---|---|---|
| 被动回复窗口 | 单聊 60 分钟、每条消息 4 次；群聊 5 分钟、每条消息 5 次；频道 5 分钟（消息收发概述 — 频率与时效规则） | 能力表 notes 写明；`reply_window_seconds` 由安装配置决定 |
| 撤回时限 | 机器人可撤回自己发送的消息，**发送超过 2 分钟不可撤回**（消息收发概述 — 撤回消息） | `RETRACT_WINDOW = 2 分钟`：超过就带着平台自己的理由拒绝（`ChannelError::Rejected`），不发一个注定失败的请求 |
| 撤回对象 | 只能撤回机器人自己的消息（消息收发概述 — 撤回消息） | 插件只寻址自己在该会话的最后一条消息 |
| 主动消息的用户开关 | 用户可在客户端关闭"允许主动发送"，关闭后主动消息一律发送失败（消息收发概述 — 主动消息） | 记录为平台事实；不写成产品门 |
| 主动群消息的所有者开关 | 2026/06/22 起全量开放，但**须群主打开【机器人主动在群聊内发言】**（发送消息 — 主动推送能力更新说明） | 记录为平台事实 |
| 频控 | 单聊：认证 10/qps & 20/qpm、未认证 5/qps & 30/qpm，1000 条/用户/日；群：认证 60/qpm、未认证 30/qpm，20/qpm 单关系，1000 条/群/日（消息收发概述 — 主动消息） | 记录为平台事实 |
| 互动召回消息 | 用户主动对话后的 30 天内分 4 个周期各 1 条，用 `is_wakeup` 声明（消息收发概述 — 主动消息 / 单聊） | 未实现；能力表不宣称 |
| 消息去重 | 同一 `msg_id` 可能多次推送，需结合 `msg_seq` 去重；被动回复时相同 `msg_id + msg_seq` 重复发送会失败（消息收发概述 — 消息去重） | 回复带 `msg_seq`（默认 1）；编辑/撤回按平台消息 id 寻址 |
| 群消息不支持流式 | 发送群聊消息 — 注意 | 群场景不产生流式 |
| 频道发送需在线 | 发送消息接口要求机器人保持 WebSocket 在线（发送子频道消息） | 安装的网关负责在线；能力表记为平台事实 |
| 消息类型 | `msg_type` 0=文本(`content`)、2=Markdown(`markdown`)、7=富媒体(`media`)、8=图文卡片(`card`)（发送群聊消息 — 请求体） | 插件的出站构造按真实类型产出 |
| Markdown 的范围 | 单聊与群聊已对所有机器人开放；**频道场景需内邀开通**（Markdown 消息 — 2026/04/23 能力更新说明） | 频道场景降级为纯文本 |
| Markdown 支持的写法 | 标题、粗体/斜体/删除线、链接、图片、有序/无序列表、块引用、水平分割线；**不支持代码围栏**（Markdown 消息 — 支持格式） | 围栏降级为纯文本行；其余保留 |
| Markdown 与文本互斥 | 传了 `markdown` 后 `content`/`ark` 必须为空（发送群聊消息 — 请求体） | 出站构造保证只有一个内容字段 |
| @ 的写法 | 群消息里 @ 某成员会被替换为 `<@` + member_openid + `>`；@全体为 `<@all>`（群消息（全量模式）— `content`） | 群场景用 `<@openid>` |
| @ 的写法（频道） | 频道消息的示例内容是 `<@!1234>hello world`（发送子频道消息 — JSON 格式示例） | 频道场景用 `<@!id>`；两个平台写法不同，不是同一套标记 |
| 引用回复 | `message_reference.message_id`：非机器人消息取自事件 `MessageScene.ext` 的 `msg_idx`，机器人自己的消息取自发送响应的 `ext_info.ref_idx`（发送群聊消息 — MessageReference） | 插件的 `[quote:<id>]` 变成 `message_reference` |
| 事件 | `C2C_MESSAGE_CREATE`、`GROUP_AT_MESSAGE_CREATE`、`GROUP_MESSAGE_CREATE`（全量模式）、`GROUP_MEMBER_ADD/REMOVE`、`GROUP_ADD_ROBOT/DEL_ROBOT`、`GROUP_MSG_RECEIVE/REJECT` 等（接口文档索引 — 事件） | 事件分类器只把已知事件变成观察，未知事件不分类 |

## 三、判定

- RT19：能力表只列 `describe` 实际能产出的动作 —— 官方 QQ 现在只宣称 send / retract / media / markdown ✓。
- 官方 QQ 的可达动作集合与官方文档逐项对照，差异写进本文件 ✓：唯一"代码有、文档没有"的动作（编辑）已经删除。
- 边界如实记录：窗口、时限、频控、开关全部写进能力表的 notes ✓，没有被写成产品审批或 allowlist。

## 边界（本文件不证明什么）

- 本文对照的是**官方文档**，不是一次真实账号的探测：本文没有用一个真的 QQ 机器人账号发过消息。
- 真实账号的可达面还受安装侧的权限影响（群主开关、用户开关、全量群消息的订阅权限），这些在文档里是"由平台侧决定"，本文只把它们记成事实。
- 撤回的两分钟窗口在本轮由插件按文档实现（超时即拒绝）；平台返回的错误码仍是最终事实。
