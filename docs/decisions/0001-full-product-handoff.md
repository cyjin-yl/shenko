# 0001 完整产品的自主开发与 PR 交付

状态：采用，已按 U51 修订。来源：U50–U51，结合 SPEC §40 的已有授权。日期：2026-10-22。

## 目的

让朋友的 Claude Agent 能通过一个持久目标自主开发完整 Shenko，尽量不向人类转交普通工程决定，同时避免阶段成果被误报为最终完成。

## 决定

- 仓库现行 SPEC、WHY、AGENTS、GOAL 与覆盖/证据记录共同提供可查依据；历史草稿明确归档。
- 全部 S1–S5 为本次开发范围，首版自开发能力优先实现，但不作为最终停止点。
- 使用真正的 Claude `/goal`、Opus 5.5、ultracode/subagents 和 bypassPermissions；官方参数为 `--dangerously-skip-permissions`，每次新进程恢复时显式带入。
- 在朋友自己的 fork 中自主开发、分支、合并、重构、调配工具/CI；多实现者通过独立 worktree/branch 和依赖合同并行，协调者负责整合与完整目标。
- PR 尽早建立、持续更新；等待人类 review 不暂停开发。默认完整集成 PR，必要时辅助 stacked PR。
- 本次交付结果是完整证据和 ready PR，上游拥有者随后 review 与合入；上游访问按实际 GitHub 权限处理。
- 朋友用自己的 GitHub 身份 fork 并 clone。仓库实际可见性、read/fork 能力和远端创建状态在交接时核对；本地资料不代表远端已经创建或配置完成。

## 为什么

持久文档与实际 Git/运行证据能跨会话接续；逐项验收避免缩水；分支隔离允许并行且减少互相覆盖。PR 是交付容器，不能让人类迟迟没 review 成为整个开发流程的串行瓶颈。身份与账户前提由实际平台决定，与工程决策的自主性分开。

## 可调整部分

可改变计划粒度、工具、验证器、分支组织、接口和内部实现。保留用户完整目标、效果事实和证据，更新该记录即可，不要新增逐次审批。真正改变用户目标需要真实新裁决，不能用维护文件的权限自行宣称用户改了主意。
