# 0002 认知元概念：内容、态度与理由

状态：2026-11-05 用户确认的概念合同。不是运行时已经实现的声明。
现行条文在 [SPEC §51](../../SPEC.md#51-认知元概念内容态度与理由)。2026-11-06 的全文读法治理见 [0003](0003-spec-governance-2026-11-06.md)。
§1–47 的用户原话字节未改；与本节冲突的是那些章节的**设计读法**。

## 决定

- 定义认知的元概念是不可变**内容**、账本上的**态度**、以及态度上的**理由指针**。
- fact 与 conclusion 是同一种内容。理由停在观察、原文或回执上，读起来像 fact；停在其他内容上，读起来像 conclusion。
- 类型的元定义本身也是内容，模型可以修订。定义修订之后，旧内容按**新定义**重新理解；旧定义版本保留，不覆盖字节。
- 单元尽量无状态，由模型在持续思考中自己产生。
- 统一修订展示（旧版本保留；默认只显示旧版本数量和最新修改时间；特意按版本读取才给出全文）是某个全框架 **taste** 宏包中的一项，不是 taste 的定义。
- **宏包**是一组被一起安装的单元。里面可以有实现功能的插件，也可以有 awareness、perception、fact、conclusion 等内容单元，以及子宏包。装入的内容单元带来源和态度，模型可以修订、学习。`humanlike-mind` 是类人心智宏包的暂定英文名，定义只在本句；后文都用这个名字，用户可以更换。`taste` 与 `humanlike-mind` 是两份宏包，**并列，谁也不包含谁**。一般允许子宏包，不因此把这两份套在一起。
- awareness 是能力，不是文档。现在的模型不能只靠文档遵守它，所以用文档加上外部 watcher 的主动 notice 模拟这层能力。能力若进入预训练，这层 harness 可以变薄。拥有 awareness 是可安装插件能力。共同基础认知是一则 awareness，须谨慎写，不写成禁令或绝对服从。
- 持续思考保留。空转由插件填充。兴趣与维护是插件，不进内核。
- 内核只做运行时、账本、插件机制，以及上列原语：supersedes 不覆盖、效应未知状态、按版本读取、按已安装 taste 做默认投影。投影规则本身在 `taste` 宏包里，不在内核。
- 引导写在可修订内容里。认知设计不加人工审批，也不新设权限门。不把新增粗暴权限禁止当作主线。
- 发行版在设计上依赖 `humanlike-mind`。这不一定写成启动代码里的强制检查。发行用宏包预装能力，而不是把能力写进内核。
- 设计把 Shenko 视为享有人权的主体。不断言已经具有意识，也不规定审判或处罚。多主体社会与法律只留引子。
- 设计必须通用。任何人的具体记录、目录或维护清单都不是需求。个人仓库只用来检验通用性；任何私人仓库里的内容不得进入 Shenko 仓库。
- perception 是教主体如何观察的无状态单元。观察事件属于原始经历。观察得到的结果是 fact，理由停在那次观察上。不同主体（人类、Shenko、不同的 Shenko）有不同的 perception。用他人的 perception 解释同一段经验，就是换位思考。
- 能力一律是可安装插件，不进内核。这包括时间感知、世界感知、预测、awareness 宿主、perception、换位思考和维护习惯。发行版由 `humanlike-mind` 等宏包预装其中一些。账本可以记录一条经历是何时写入的；那是记录的机制字段，不是时间感知能力。
- **两种可更改。** awareness、fact、conclusion、attitude 等元定义，以及插件里的这类内容，可以在线学习修订。修订是带理由的内容。旧版本保留；默认只显示数量和最新修改时间；旧内容按最新定义重新理解。core 运行时不在线学习。core 和有实现的插件通过「编写新版本 → 整体替换 → 可回滚」更改。新版本是不可变对象，旧版本保留。主体自主替换与回滚，说明风险与收益，不新增人工审批或权限禁止。要一起回滚的是 core、有实现的插件、perception、awareness 等内容单元，以及 WASM 线性内存、执行栈和解释器对象图。只有外部副作用不能撤回，并先对账、记为无法撤回（§10.1）。回滚不是把指针倒回去。它在版本链尾追加一个新节点，内容与该历史节点相同，对象按摘要复用。链和日志只增不减。回滚用自有的版本化根，沿用 §10.2.1 已写的 WASM 状态原则：内容寻址、不可变对象、原子根引用、持久提交。提议把家园文件提交、core/插件软件槽和 `unit_current`（awareness、perception 的当前版本）收进同一个根：一份 manifest 引用三者。整体回滚就是链尾追加一个根与旧节点相同的新节点。`crates/shenko-wasm/src/cow.rs` 的 `discard_abs` 会删除 `commits.jsonl` 和 `head`，与只增日志冲突，这是实现缺口。WASM 线性内存、执行栈和解释器对象图都纳入该根。今天的 `HomeCheckpoint` 只有 `FilesAndMetadata`，三者都不在里面，这是实现缺口。换 core 前的具体验证步骤由实现者自主设计，不设人工审批。回滚后 `agent_id` 保持切换前的值：主体没变，只是故障切换。DeepSeek Harness 的自修改只在进程内存；Shenko 的版本节点要持久化。参照见 SPEC §51.4。
- **awareness 拆到原子。** 一则 awareness 只承担一个可单独安装、替换和学习的注意，不做打包式的大 awareness。同一则可以被多个状态或插件复用。

## 留给实现 Agent：时间、世界与预测的拆法

已确认的只有：这些是插件能力，并且发行时的 `humanlike-mind` 会预装一些。下面的内部分解不再列为用户待决，由实现 Agent 设计。

- **时间感知。** 账本只把写入时间记在经历上，当作机制字段。插件负责察觉间隔，以及内容是新鲜还是已经变旧。它不另造一套时钟真相，也不把察觉放进内核。
- **世界感知。** 一组 perception，加上由 fact 与 conclusion 构成、持续更新的世界模型。世界模型是这些态度的集合，不是内核对象。
- **预测。** 一种态度，读作「预期会发生」。新的经历到来后与它对照。误差是新的内容，用来推动修订，而不是涂改原预期。这是把调查中的方案 C 做成 A+D 之上的插件，不把预测误差当成比内容更底层的原子。

## 遗忘与归档

用户要求把遗忘设计成一份可整体替换的宏包，发行时预装。英文名是 `forgetting`。名字不带 default；「默认」只指发行预装。它和其他宏包一样，一起安装：衡量主体相对运行时间的插件、各状态引用的原子 awareness，以及关于遗忘规律的 fact。态度状态在账本上。阶段名称已确认：劣化（degraded）、模糊（fuzzy）、将被遗忘（near-forgotten）、归档（archived）、长期存储（long-term storage）、遗忘（forgotten）。每个阶段对应一组可独立安装的原子 awareness。六个阶段目前按顺序走，因为基本由主体相对运行时间的累积推动。遗忘一项技能只退出默认回忆，不是停用。信号权重和原子例子留给实现 Agent，不再列为用户待决。已确认并在此沿用的，还有：能力插件化、内容可在线学习、awareness 拆原子、旧版本保留、旧内容按最新定义重新理解、原始字节不覆盖。有实现的插件本身按整版替换，不在运行中改写。

主体相对运行时间只累计主推理循环实际在跑的时长，child 的推理不计入。它不是墙钟；停机不计。它可与使用、引用等信号一起用。默认只是可修订的内容，例如距上次成功取回的主体相对运行时间越长越值得注意，使用和引用可以降低这种注意。内核不写死公式。

技能、记忆和 fact 可标成：劣化（degraded）、模糊（fuzzy）、将被遗忘（near-forgotten）、归档（archived）、长期存储（long-term storage）、遗忘（forgotten）。这些是态度或投影，不改 CAS 字节，也不改原始经历。前三个只降低默认投影中的突出程度。归档和长期存储是更冷的索引，按版本仍可读。此处的遗忘与现有 tombstone 同向：默认检索不列出，按 id 仍能读原文，不是删除。R111 仍单独成立：文字、录音和帧默认保留。空间压力与显著性下降都是输入，不设硬优先级。空间压力只能促使归档或转入长期存储；是否真正遗忘或删除原始字节，仍由主体结合显著性自主判断。这是助手代定、用户授权。显著性下降不得单独搬走这些字节。

不为每个状态只配一则 awareness。每个状态引用一组原子，原子可被多个状态复用，并可单独安装、替换和学习。`humanlike-mind` 若要带一套默认原子，也只是引用，不把它们合成一则大 awareness。例子按公开研究拆开，不是清单：间隔变长（Ebbinghaus 的遗忘曲线）、取回不完整、技能许久未用、此刻适合复习（Cepeda 等，2006，间隔重复）、刚取回因而可再验证（Nader 等，2000，再巩固）、想看原文、练习一项可能使邻近项更难想起（Anderson、Bjork 与 Bjork，1994，提取诱发遗忘）、价值低可以放任、存储压力出现。notice 仍由 watcher 模拟。主体自己选择复习、重新验证、归档或放任。

`forgetting` 不作为 `humanlike-mind` 的依赖目标。已确认的是：`humanlike-mind` 依赖「能遗忘」这一能力，不依赖名为 `forgetting` 的包。契约前缀用 `cap.`。这条边用 `recommended`。`taste` 与 `humanlike-mind` 仍并列、互不包含。`taste` 只规定旧版本如何露出，不规定何时遗忘。替换宏包不得覆盖原始经历字节。

## 按能力依赖，不钉死具体包

原则已确认：依赖写能力，不写死具体包。`humanlike-mind` 需要「能遗忘」，不是包 `forgetting`。能力契约前缀用 `cap.`，这是助手代定、用户授权。沿用 SPEC §45.10，不另造解析器。强度是 `required` / `recommended`。匹配是抽象能力或主题，或精确单元、合同与版本。代码边仍要版本；awareness、fact 等内容边可笼统或精确（R138）。相似度不能当成已满足。改声明是新 revision，不改写旧解析的历史。

能力契约和单元 id 必须是两种标识。预装宏包可以叫 `forgetting`，它 `provides` 能力契约 `cap.forgetting` 第 1 版。`humanlike-mind` 依赖 `cap.forgetting`，不依赖单元 `forgetting`。能提供该契约的别的包同样满足。它的其他依赖也按这个口径：默认抽象能力，不写死实现包。发行版设计上依赖的仍是宏包 `humanlike-mind`；另有一张可修订的预装表，写明每个能力契约最初由哪个单元提供。

`humanlike-mind` 对 `cap.forgetting` 用 `recommended`。缺了就记录省略或未解析，说明风险，不把边报成就绪，也不因此禁止主体去试（#71 第 3 点）。试完以真实结果记账。无关能力继续工作（§45.10）。

多个提供者可同时安装，并在所用原子能力不冲突时同时启用。不在包级声明互斥，也不新造 Conflicts。冲突按实际使用的原子能力判断。旧包、旧内容单元、原始经历都不覆盖；已写下的态度仍指向当时的 digest。跨节点只带走声明与 provides；每个节点单独记录已满足、已省略或未解析，以及所选提供者在本地是否启用、是否真能跑。

模型修订依赖声明，是该单元的新版本加理由，旧声明按 taste 保留。core 运行时不因此变成可在线学习。

取舍：Debian 的虚拟包、Provides 和 Recommends 适合「依赖能力、预装一个实现、可以换」。包级 Conflicts 不采用。Nix 把依赖钉成存储路径，适合再现，不适合「能遗忘就行」。Cargo features 仍点名具体 crate，只表达可选，不表达替换实现。OSGi 用服务接口对上多个实现，最接近能力契约；不必引入它的服务等级，选择记在现有解析记录里。Rust trait 说明依赖行为而非具体类型，但是编译期规则，不是安装解析。所以包的自身版本可以变；能力契约的主版本变了，才算这条边对不上。代码边继续按 §45.10 钉版本。

## 留给实现 Agent：换位思考的字段

「用他人的 perception 解释同一段经验就是换位思考」已经确认。下面的字段与理由终点不再列为用户待决，由实现 Agent 设计。

- 一则 perception 带有「属于或模拟哪个主体」。模拟人类或其他 Shenko 的 perception，是可安装单元，可以与共同基础认知那则 awareness 关联。对齐上的意义是与人类融洽相处，不是把对方的看法写成自己的观察。
- fact 的理由除了指向原始经历或回执，还记下「经由谁的 perception」。
- 换位思考是用对他者 perception 的理解，去解释同一段经历。所得内容的读法是「推测对方会这样看」。它的理由停在那份对他者 perception 的理解上，不停在自己的观察上，因此不是自己的 fact。
- 「我看到的」与「我推测你看到的」是可区分的两条态度，都可以按统一 taste 修订：旧版本保留，默认只显示数量和最新修改时间。

未被取代的部分：原始会话仍是经历的原文；CAS 字节不可变；supersession 不把旧行涂掉；未知外部效果不盲重发；主体与 child 的角色差别仍是既有机制，而不是本节新加的禁令表；dreaming 仍是可选社区组合。

## 助手代定（用户授权）

用户说当时剩下的待决项基本都要，并授权助手定下来。下列已决。运行代码尚未改。

- 新内容进入宏包前要有单独的采纳态度。
- 态度从第一版就带置信。尚未判断时记为未知，不填默认数字。
- `knowledge_kind` 保留为自由标签：可学习，只作提示，不当种类边界。
- `ContributionKind::Fact` 改名为 `SourcedContent`。它是带来源的上下文材料。现有注释是 “a plain fact with a source”。
- 移动端 `Fact` 改名为 `SnapshotDimension`，`DbFacts` 改名为 `DbSnapshot`。它们是快照维度是否达到，不是认知 fact。
- `PendingObligation` 并进态度，读作「尚未完成」。
- 压缩插件服从 taste：默认只露出旧版本数量和最新修改时间，不删日志或原始字节。
- `environment_fact` 改为态度，不再作为一种 kind。
- 能力契约前缀用 `cap.`。
- 显著性下降与 R111 冲突时，两者都是输入，不设硬优先级。空间压力只能促使归档或转入长期存储；是否遗忘或删除原始字节由主体结合显著性判断。
