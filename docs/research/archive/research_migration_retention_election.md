# D7 / D8 / D9 / D11 增量协议建议

本文件只提出产品合同和验收；没有开发、运行集群或验证性能。用户已确认的四项裁决如下；其余具体机制标为可直接进入草案的建议默认，不另设用户审批。

| 裁决 | 已确认含义 |
|---|---|
| D7 | 接受额外磁盘成本；可随时 breaking change；自主更新采用旧副本继续运行、迁移数据、烟测新版本、最后迁移自身。更新与迁移通过插件实现。 |
| D8 | 原始文字、录音和屏幕帧默认永久保存；空间不足时主体自主决定遗忘或迁移到用户自有云盘等位置，通过插件执行。 |
| D9 | 自主兴趣可以长期持续投入，没有一到统一期限就必须放弃兴趣的要求。 |
| D11 | 在线节点可接管，以持续在线优先；出现多个主体时动态投票选出新主体，合并旧记忆和任务。网络分区可暂时形成分支，每个分支仍是单线程主体。 |

## 1. 四个必须分清的承诺

1. **分支内串行**：同一 `branch_id` 的主思考序列只有一个可提交的运行 incarnation，按 `turn_seq` 推进；主体继续只委派、调用语义 memory 接口，具体文件/迁移/合并由子 Agent 和 runtime 执行。
2. **连通后的统筹主体**：获得有效选举结果后选出一个 canonical 主体；其他已观察到该结果的分支在安全边界移交，成为归档分支或有限 worker。分区中允许多个真实活跃分支，不把它们说成仍然全局唯一。
3. **历史事实保留**：选举落选、软件回滚和快照恢复都不能改写已经发生的外部副作用。主动真实删除依据 D8 独立进行，留下不含被删除内容的必要状态与删除标记，防止恢复时复活数据。
4. **可用性的物理边界**：有可运行节点、可用模型与必要依赖时尽量持续；所有节点断电、模型全部不可达、设备无可用空间等情况下不能保证继续思考。分区期间同时保证全局单一线性历史和每一侧持续响应，在一般网络故障模型下不可兼得。[S1]

以上边界不要求任何源码永久不可改。更新器、选举器、存储适配器、验证器、bootstrap、kernel、rescue 均可由 Agent 替换；候选切换时维持可启动旧闭包和清楚的状态交接。检测网络故障的心跳定时器不替换持续思考循环。

## 2. D7：保留运行旧副本的迁移协议

建议 `SelfUpdateProvider` 组织过程，`MigrationProvider` 执行数据与协议转换；自主主体决定目标和时机，有限迁移 worker 操作候选。默认状态流：`prepare → copy → catch_up → smoke → handoff → observe → retire_old`。

1. **prepare**：建立候选 B 的完整软件闭包，覆盖依赖、插件、引擎、配置 schema、启动/救援组件及其读写版本。保留当前 A 的可启动闭包与数据视图。允许远端交叉构建和远端迁移；额外磁盘是接受的成本，不要求路由器同时本地编译整套工具链。
2. **copy**：从一致性水位 `w0` 复制原始事件、对象引用与业务数据，转换到 B 的新格式。A 继续服务；新增事件进入可追赶的 journal。拷贝对象先完成内容和校验，再发布引用；保留尚未追赶的 journal 和迁移引用，防止 GC 抢删。
3. **catch_up**：持续应用 `w0` 之后的事件。迁移记录输入水位、目标水位、转换版本和对象闭包校验。此阶段的双份是两个格式视图；不要让两份应用同时向同一文件树独立写入。
4. **smoke**：B 实际启动并检查数据读取、查询索引、工具协议、插件、模型调度、消息恢复和退出恢复。使用记录回放或明确隔离的测试资源，烟测不把真实 outbox 再发送一次。候选的模型测试照常取得实际 broker 许可。
5. **handoff**：达到切换条件后，在主思考轮次边界阻止 A 新提交本分支决定，记录在途动作和未决结果，追平最终水位 `w1`。转移 inbox cursor、outbox、任务与联系人状态、权限 revision、原始记忆引用、长期兴趣、删除标记，以及 active / reserved / cancel-pending / unknown 模型请求。最后迁移人格、当前思考状态与持续意图，提交新 incarnation，再把路由切给 B。
6. **observe**：A 的旧闭包和恢复进程仍可用，但不与 B 同时提交同一分支的新思考。B 启动失败且尚未产生新事实时，A 可直接接回；B 已产生新事实时，须导入这些事实并恢复相应任务/副作用状态，再由 A 或修复候选接回。
7. **retire_old**：至少保留一个独立可启动、确实可读其恢复视图的前代闭包，直到下一轮已经形成替代恢复路径。依照 D8 自主保留策略回收更老版本；不能只因版本号旧就回收迁移仍依赖的读码器、密钥引用或对象。

**Breaking change 的具体语义**：新版本可以采用完全不同的数据库 schema 和插件 ABI；不要求永远兼容旧代码。恢复合同要求保住事实和可恢复路径，因此新格式原始增量须附可获得的解码/迁移组件。不能把“允许 breaking change”解释成“候选失败后可丢掉切换后的全部历史”。逻辑 journal envelope 自身也可升级，但升级期间必须有明确版本协商和读取路径。

多节点更新采用节点兼容矩阵和滚动/成批迁移计划。互不兼容的版本先通过桥接适配器交换事件，或保持隔离分支，直到合并 worker 能解释两侧格式。一个节点启动成功不证明整个集群协议迁移已经完成。

## 3. D8 / D9：永久默认与自主回收

建议 `RetentionProvider` 使用 `permanent_by_default`；文字、录音、屏幕帧都没有隐含 TTL。持续兴趣对象也不按统一任务期限过期。长期兴趣可以由多轮有限 worker 接力，每轮归还推理许可、报告阶段结果；主体可持续投入同一兴趣，同时执行既有紧急程度、公平性和实际资源合同。

空间压力下的建议默认顺序是：清理可重建缓存与临时文件；去重/无损压缩；迁移原始资料到已接入的用户自有存储；必要时由主体自主选择真实删除。此顺序是可替换策略，不是永久禁止主体选择遗忘。`semantic_forget`（降低/停止 recall）、`archive_move`（改变保存位置）、`erase`（删除内容）使用不同意图和回执。

| 操作 | 必须满足的合同 |
|---|---|
| 迁移 | 目标认证、内容 hash、对象闭包、manifest、可读密钥引用和一次读回验证均完成后，才释放对应本地唯一副本；上传请求收到成功不等于完整资料可恢复。 |
| 原文删除 | 主体选定范围与原因，worker 执行；同步处理对象、FTS/vector、摘要、Git 历史、可控导出与备份。记录实际释放量和仍不可达的远端副本，不能宣称已经删除所有副本。 |
| 分支合并 | 针对已删除对象的有效墓碑优先于普通恢复/同步；默认 delete-wins 只作用于其明确范围，不能用泛化 LWW 擦掉无关记忆。新内容与重新授权保留使用明确新事件。 |
| 恢复 | 先应用删除标记与保留策略，再开放旧快照查询；缺失原文显示缺失，不能由摘要重造后冒充原文。 |
| 快照与 GC | 根集合包含活跃分支、候选迁移、恢复版本、未决动作和归档 manifest；先可靠发布新引用或删除标记，再回收已无引用对象。内容已被真实删除时，旧快照也须失去对应访问能力。 |

空间预警应提前作为消息进入持续主体。建议预留少量 journal / 控制状态空间，并允许主体事先委派压力策略。如果存储突发耗尽且模型不可用，runtime 只执行已授予的回收/迁移策略；确实无法继续捕获时显式记录时间范围和丢帧/缺口，不静默删除未被选中的原始历史。默认永久是保留策略，不是无限磁盘承诺。

## 4. D11：投票、分区分支与重连收敛

### 4.1 建议默认：共识控制面 + 可分叉事实面

`LeadershipProvider` 使用经过验证的 Raft 类实现记录 canonical 主体、成员集合与交接决定；`BranchJournalProvider` 独立保留所有分支的事件 DAG。**个人事实不能只存在于 Raft 未提交尾部**：Raft 为统一控制日志会覆盖冲突的未提交项；个人分支中的已观察事实、真实外部回执和记忆必须作为独立带 ID 的事件导入，不能因此被抹掉。[S2]

- 节点身份持久、认证、去重，一个节点身份一票；主体创建多个分支不增加票数。成员加入可由 Agent 在既有授权的节点范围内自主完成；发现节点不等于已经更改投票成员集合。
- canonical 选举使用协议所规定配置的法定人数；绝不把“当前碰巧能看见的节点”当作新的全体。成员变更使用所选实现经验证的重配置协议；Raft 原论文给出的 joint consensus 要求过渡时满足旧、新两组多数。[S2]
- 对主体的“动态投票”由可替换选举策略表达。数据可解释性、可用模型、健康度可影响候选偏好；不能绕过底层日志完整性与投票规则。选举结果和理由入控制日志。
- 初始故障检测草案可用 2 秒心跳、静默阈值 `max(10 秒, 5 × 近期 p99 RTT)`、1–3 秒启动抖动；这些是可调整的初值，不是已验证恢复 SLA。心跳只检测节点，不把主体改成低频 Tick。
- 获得正常 quorum 时选 canonical 接管者。没有 quorum 但仍有可运行节点时，创建明确的 availability branch，继续自主思考和既有授权范围内的工具委派；不伪称其为全局选举获胜者。仍连通的孤立节点可协商局部统筹者，但记录其作用域，不擅自缩小全局成员集合。
- **接管不冒用旧分支**：未确认原运行实例停止时，即使已取得 canonical 选举结果，接管实例也从已知水位建立新 `branch_id`；旧节点可继续它原有的分支。只有已确认的 handoff 才能在同一分支内更换 incarnation。节点本地也需防止两个进程同时提交同一 incarnation；心跳超时不是旧进程消失的证据。

每个事件至少有 `agent_id / branch_id / node_id / incarnation / local_seq / event_id / causal_parents / schema_version / scope`。墙上时钟只供人阅读；断网分支不能凭时钟较新就覆盖另一分支的历史。

### 4.2 重连时的收敛顺序

1. 双方验证身份、协议版本、已知成员配置和事件水位，先交换缺失事实与删除标记；一个节点的传输失败不影响另一节点既有事实的留存。
2. 连通的有效投票集合选出 canonical 统筹者；底层共识日志完整性规则优先。没有有效 quorum 时保留显式局部状态，继续尝试收敛，不虚报全局唯一。
3. 已看到有效交接结果的非 canonical 分支停止产生新的主体决定，在安全边界交出在途任务和工具回执；尚未收到结果的分支仍可能继续，真正的资源排他性由目标端执行的 fencing 决定。
4. 有限合并 worker 对事实按稳定 `event_id` 去重并保留来源，渠道消息再用 provider/account/message ID 去重。记忆冲突并列保留，主统筹者形成可追溯的新判断；不对全部记忆使用最后写入覆盖。
5. 已有成功回执的任务不能退回“从未执行”；失败与 unknown 区分。重复任务可合并后续计划，但不能删掉两次真实执行的记录。人格、兴趣与待办差异由主体接纳、调整或合并，并形成新的决定事件。
6. 所有已知分支的导入水位、对象闭包与墓碑应用完成后，标记一次 merge 完成。未连接的旧分支以后出现，仍按同一协议追加导入；不能承诺永久分区也在固定时限内收敛。

### 4.3 外部副作用和模型容量

每次外部动作有稳定 `operation_id`、意图、目标资源与 `pending / succeeded / failed / unknown` 回执；重试优先复用目标支持的 idempotency key。目标支持 fencing 时，由资源端验证单调令牌并拒绝过期写入；仅在日志里写 epoch、或仅让本机租约过期，挡不住旧节点恢复后继续写入。[S3]

分区分支拥有工具自主性，同时系统如实承认：不支持 idempotency / fencing 的外部系统可能发生重复或并发动作。重连不能“回滚事实”；查证、补偿、撤回是新的显式任务。`unknown` 不能自动当成失败重做，也不能自动当作成功。所有动作仍受已存在的资源授权约束，不增加按次人工审批。

**全局模型 C 仍按实际物理资源域计算。** 多分支共享同一 engine 时，通过该 engine 可达的统一 broker/gateway 串行或限并发；失联分支不能各自拿一个完整 C 再访问同一后端。无法确认结束的旧请求仍占其容量。需要继续思考的分支可以使用已经授权且独立的其他 engine 资源域；KV lease 绑定真实 backend epoch，不能把 slot ID 复制到另一设备当作缓存迁移成功。

同一分支的未知旧 attempt 不能被新 incarnation 重复接管提交；D11 允许的是显式新分支继续，随后合并其真实历史。这个区别同时保留用户的在线优先与既有硬并发合同。

## 5. 最少验收与主稿修改点

验收按真实 API history 检查产品声称的性质。Jepsen 的一手方法覆盖分区、延迟、进程暂停/崩溃、时钟、断电与磁盘故障，以及已确认写入不丢、状态单调和最终收敛；这里采用这种故障思路，不声称本产品已经通过 Jepsen。[S4]

| 场景 | 必须能观察的结果 |
|---|---|
| A 运行中迁移 B；copy / catch-up / handoff 任意点崩溃 | 原始事实有明确水位，至少一个闭包可启动；已发 outbox 不盲目重发；切换后的事实不被旧快照吞掉。 |
| B 更改不兼容 schema 并产生新数据后损坏 | 保留原始增量及解码路径，通过恢复/修复接续；不能仅以 A 可启动证明数据恢复成功。 |
| 单节点、两节点分区、三节点多数/少数分区 | 分支可自主继续且 branch ID 清楚；每分支串行；无 quorum 的分支不伪造 canonical 授权。 |
| 旧主体长暂停后继续写；迟到回执 | 支持 fencing 的资源拒绝过期写；不支持者的真实结果保留并可核对，unknown 不被臆断。 |
| 分区中一侧删除，一侧持旧快照，随后重连 | 删除范围和墓碑生效，旧正文/派生索引不会被同步复活；保留其余无关事实。 |
| 云盘只上传部分对象或密钥不可用 | 不提前删掉唯一完整本地副本，显示迁移未完成。 |
| C=1 且分区/更换 broker/旧请求未知 | 实际同资源域从未因接管超发；独立 engine 的分支恢复有独立容量账本。 |
| 长期兴趣经历升级、离线、分叉与合并 | 目标、证据和进度接续，worker 可更替，持续主体未被固定轮询任务取代。 |

主稿需要同步的具体旧表述：§5.1 / §5.4 将“任何时候全局唯一”改为“每分支单线程、连通后选主收敛”；§9.2 补 copy / catch-up / 最后迁移自身；§12.4 改默认永久和自主空间处置；§13.4 区分同分支重复续写与合法新分支；§28 D7/D8/D9/D11 从开放问题移入已确认。图中的“唯一主体”可加“每分支；连通时 canonical”注释。原先禁止“网络分区产生第二个自己”的句子已不符合最新裁决。
