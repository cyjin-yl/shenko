# 研究补充：Scaling Discovery Requires Forgetting 与研究子 agent 的可控重启

研究截止：2026-10-22 18:20 UTC / 2026-10-23 02:20 Asia/Shanghai。范围是论文核验与产品设计推论，不包含开发。以下将一手论文事实、未证实部分和本产品建议分开。

## 2. “遗忘”对象和永久档案不能混为一谈

原文 §3.1、§3.3 与附录 B 支持的是**新一轮 agent 的可见状态控制**：既不续接旧 session，也不给它旧候选集合与生成过程；仍有任务、规则、最佳成果和评分。它并非只有一次 context compaction，也不是把模型权重中的知识删除。

尤其要区分两个层次：§3.3 说 harness 保存历次 session script，又由 reducer 决定下一轮给 agent 看哪些候选、继续哪个 session；遗忘时改为新的 search state。因此不能把文章里的 discard 自动解释为“磁盘审计档案、备份、所有 git object 均已物理销毁”。论文也没有建立用户数据擦除协议。

**尚未核实的实现细节：** 论文未在已获取内容中提供可归属作者的代码链接；作者主页、GitHub 仓库及代码搜索未定位到官方实现。最佳候选是否经过路径白名单导出、是否连代码注释中的失败叙事也清洗、物理存储如何回收，不能声称已被实现和验证。附录提示工作区附带脚本也可能被提交，所以“最佳候选”不能擅自改写成“只剩一个源文件”。

GitHub 检索发现 [tatra-labs/lethe](https://github.com/tatra-labs/lethe)，其 README **明确写为 independent implementation**。已用 GitHub 插件读取 README，blob SHA `7e176ec378e5bda000308f4f86f22270758d211c`。它可作为后续实现参考线索，不能称为论文官方代码或原实验复现证明。它自己的 README 描述保留旧轮次供检查、下一轮使用新仓库，正好说明“不可见”与“删除”是不同设计维度；本次没有审计其代码。

## 3. 对证据强度的判断（我们的分析）

下列判断是对实验设计的分析，不是作者已证明的额外结论。

1. **可以支持尝试这种完整重启政策，不能定位唯一成因。** 同时改变了会话、工作区历史、候选可见范围和首次指令重申；缺少只清会话、只清搜索文件等拆分对照。更大修改、更多 reasoning tokens 与收益同时发生，不足以证明是其中某一个变量单独造成收益。
2. **主表也含团队共享效应。** 最强方案同时拥有共享候选与重启；不能将相对独立并行的全部提升都归为遗忘。停滞状态对照提供了更直接的额外支持，但覆盖范围更小。
3. **单一模型/harness、少量任务和重复不足以推出普适保证。** 不能承诺小型量化本地模型、中文资料研究、日常群聊和没有明确评分器的任务有同样收益。均值、标准差与最大改善应一起理解，不能只留下最漂亮的百分比。
4. **固定重启不是最优停止规则的证据。** 本产品需要决定何时重启、何时暂缓、何时关闭某项研究；本文没有给出已经验证的通用阈值。不能直接把三次或固定时长写成所有任务的永久默认。
5. **成本要重新以本地推理现实测量。** 模型美元花费不等于 GPU 时间、能耗、prefill 延迟、cache 命中率和前台请求等待。短上下文可能更省，但新的 KV prefill 也有代价；团队宽度更大不代表小 GPU 必须同时执行更多请求。
6. **“共享免费”必须谨慎表达。** 文件/commit 交换可以减少专门的对话消息，但模型读候选、diff 和反馈仍占上下文与输入处理。本产品不能据此宣传子 agent 沟通零推理成本。

### 评分与泄露：本产品必须补足的验证边界

“最佳”总是相对于某个评分器、样本集、环境和版本。一个候选赢了可见开发集，不代表它在新任务、真实部署或隐藏测试上也更好。重复搜索还会不断挑选偶然高分；这是我们需要主动处理的选择偏差，而非指控该论文出现作弊。

SPEC 应当明确：候选不能修改评分器、评价数据或记分结果；验证器与可写工作区处于不同权限域。每条分数记录绑定候选内容哈希、评估协议/数据/环境版本、随机种子与预算。对噪声指标复测，使用未参与持续优化的验收集合决定晋升。不得把长期自我改进的“越过旧分数”作为修改权限、泄露隐私或改变既有承诺的通行证。

此外，fresh worker 的旧历史可能从很多侧路重新进入：共享 FTS5 检索、旧 git 对象、reflog、挂载的报告、兄弟 agent 发来的总结、工具错误详情，以及主循环自由撰写的 handoff。需要控制的是这些信息入口，不只是 messages 数组。

## 4. Drew Breunig 的 Context Inertia：来源与边界

已确认作者原文：[Context Inertia: When Agents Won’t Let Go](https://www.dbreunig.com/2026/10/14/context-inertia.html)，页面日期 2026-10-14，refs `turn53view3`、`turn54view1`、`turn59view0`。

他用该名称描述模型持续沿用上下文中的假设或子目标，即使新证据已经要求改变方向。文章把几项研究放在一起讨论，并提醒普通压缩可能保留甚至强化既有方向。这是术语与观察的第一手来源，**不能用博客替代论文对具体实验的证明**，也不等于“所有压缩方式都必然无效”。

两项相关论文已另行核实摘要，只作方法边界对照：

| 方法 | 重建何种上下文 | 保留的工作状态 | 一手来源 |
|---|---|---|---|
| 本篇 Forgetting | 按轮重建团队 session | 当轮最佳候选；排除旧可见搜索历史 | [2610.20563](https://arxiv.org/abs/2610.20563) |
| Fork-and-Flush | 周期性分出 fresh-context 分支 | 继承累计 workspace，再择优续行 | [2610.07447](https://arxiv.org/abs/2610.07447)，2026-10-05，ref `turn56view1` |
| Stateless Language Agents | 每次调用重建角色特定 context | harness 持有研究状态；Advisor 分配 Worker 实验 | [2610.07625](https://arxiv.org/abs/2610.07625)，2026-10-06，ref `turn56view2` |

不能把它们合称为同一个具体算法。可借鉴的共同方向是把**工作成果、证据和对话轨迹分开管理**，明确决定下一次模型调用可见什么。

## 5. 本产品建议：仅对研究子 agent 做可控重启

以下是建议进入 SPEC 的新设计，不冒充论文原实现或已经验证的性能结论。

### 5.1 主体连续性保持不变

用户已经明确：唯一主 thought loop 持续存在、单线程；直接能力仅委派、读记忆、保存记忆，不执行外部操作、不直接写文件。研究重启由负责该项研究的子 agent 提出，由 runner/记忆与进度子 agent 执行对应持久化协议。主循环接收结果并选择下一步，不因子 agent 停滞而另起第二主体。

重启不替换或清空主体人格原文、用户指令、长期承诺、权限、身份、已发生的外部行为。主循环日后必要的预算压缩/恢复属于独立机制，不能拿本论文为“删除人格与责任”背书。

### 5.2 拆成五类状态

| 状态 | 研究子 agent 重启时的行为 |
|---|---|
| 主体身份与规范 | 不变。由受版本管理的稳定来源提供；人格不授予额外工具权限。 |
| 任务契约 | 继承当前有效目标、范围、约束、验收方式、权限域、累计预算；保留用户纠正和不可重复执行条件。 |
| 最佳成果 | 仅注入已验证候选、必要运行文件、相关分数与可重复验证的证据引用。 |
| 活动搜索视图 | 创建新 session、新候选视图和新轮次；不自动继承旧失败故事、讨论与全量候选池。 |
| 审计与真实历史 | 仍由外部证据库保存，受用户保留/删除政策约束；默认不挂载给新 worker。 |

这使“需要忘记才能重新探索”与“需要历史才能诚实回忆”同时成立：**退出当前上下文，不等于抹除真相源。** 如果用户以后要求真正删除数据，应走独立删除及备份处理流程。

### 5.3 最小的重启清单

每次重启形成结构化记录，至少包含任务 ID、工作轮次、reset ID、触发原因、累计花费、基础候选哈希、评估协议版本、保留文件清单、当前权限/可见域、是否仍有未决外部效果，以及新的 session/cache 身份。

流程建议：

1. 在已完成一次候选提交的边界请求重启。先确认没有会因新旧 worker 同时存活而重复执行的 SSH 作业、发送消息或后台任务；对未知结果保留 pending/unknown，而不是当作未发生。
2. 记忆/进度子 agent 将证据、运行状态、评分与原因持久化；runner 用幂等 reset ID 执行状态转换，崩溃后可继续完成而不多开一次。
3. 由独立验证器选定可恢复候选。只有“已验证”和“适合再次执行”的文件进入 seed 清单；未验证高分不能直接成为恢复基础。
4. 创建干净的活动工作区和 session。若采用 Git，导出选定成果到新的历史根；不将旧对象目录、旧 reflog 和旧轮次报告一并挂载。
5. 新 worker 获得相同任务契约及剩余预算，重新申请推理资源。旧 worker 的 delegation epoch 失效，晚到的结果只入档，不越权覆盖新状态。
6. 对比本轮进展，决定继续、再试一次重启、换方法或将该项研究标记为暂缓/完成；主体 thought loop 仍继续选择其他工作。

### 5.4 不应清除的事实与可选择忽略的判断

应该带走：确证的接口限制、用户明确否决的动作、已执行的外部变更、撤销状态、预算、权限，以及必要的环境信息。可以先不带走：某个旧 worker 自信但未经实验的“这已经是极限”“这条路线不可能”等结论。

保留约束摘要时须包含证据引用与置信状态，避免把失败叙事重新压缩成强硬规则。允许新 worker 请求有针对性的回忆；该请求记录原因、范围与所引入的旧材料。访问档案之后，本轮应标记为“已引入历史”，不要继续声称严格执行 best-only 实验。

### 5.5 与全局并发、KV cache、递归子 agent 的关系

重启只改变研究会话，不重置全局任务预算、后代数量或优先级。累计预算按任务树追踪；不能通过换 session、再 fork 或换节点获得新的隐形额度。

研究宽度是待运行分支数，不等于模型 API 的并发请求数。所有 fresh workers 仍经过唯一推理 broker；等待其他 worker 或评估器时不持有推理 permit。主循环的思考与群聊请求仍按既定公平/优先政策调度。

旧 session 的 KV 后缀不能被当成新 session 的上下文继续使用。若后端支持，可复用完全相同、权限允许的稳定 system/tool 前缀；为新轮次重新分配 slot/cache lease，并让成本统计显示真实 prefill 开销。版本或可见域变化需要进入缓存身份判断。这里“能否复用、复用多少”是后端能力，不承诺通用零损耗。

## 6. 触发条件与收敛：先设可验证政策，再调参

推荐把固定轮次、指标停滞和证据矛盾三类触发做成可配置策略。可以观察连续无有效候选、重复尝试、指标无改善、约束理解错误等信号；不能用编辑行数或 token 数直接评价研究质量。小补丁可能正是最佳修复，大段改写也可能纯属噪声。

在代码/性能任务中，用明确验证器评估新候选。开放资料研究则先定义证据覆盖、出处独立性、关键未知、矛盾解决和用户验收，不能拿输出长度或模型给自己的分数判定“最佳”。没有可靠评分时，重启可作为换视角的探索手段，不应自动晋升为事实或已完成结论。

主循环永不退出，不意味着每一项子研究永远继续。对单项工作，预算耗尽、边际收益不足、需要新信息或已有足够可用结果都可以结束/暂缓分支；持续主体接着选择下一件工作。这种分离才与用户既要持续主动、又要 deep research 能收敛的要求一致。

## 7. 建议列入 SPEC 的验证项目

这不是现在进入开发或执行测试，而是后续验收设计：

- 比较继续原会话、普通压缩、只换 session、同时换 session 与搜索视图，以及固定/自适应重启；不要只比较两个综合方案。
- 对齐并报告本地实际资源：总推理/评估 GPU 时间、有效候选数、墙钟时间、前台 p95 等待、prefill/cache 命中和峰值内存；模型美元费用只是可选维度。
- 检查新 worker 不能自动从 FTS5、旧 Git 对象、共享挂载或其他 worker 的任务说明取回被排除的叙事；有意回忆仍可走显式协议。
- 检查重启前后的任务契约、用户纠正、预算、权限与主体人格完全连续；重启不得重新授予已撤销权限。
- 在工具执行中、评估完成后、档案提交后和 fresh worker 启动时模拟崩溃，验证不重复发送、不丢 pending 状态、不产生两个有效委派 epoch。
- 验证 noisy best、损坏候选、评分器版本变化和私密数据误进入成果文件时不会自动晋升。
- UI 显示“本研究分支换了新视角，沿用成果 X”，提供原因与真实结果；不宣称主体被洗脑、人格重生，或伪造重启后的内心独白。
