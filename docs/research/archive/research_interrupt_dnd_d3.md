# D3 增量：外部打断、主体决定免打扰、误过滤自主修复

适用范围：接入用户对 D3 的回答，供产品 SPEC 合并。仅提出设计与验收；不修改主稿，不开发实现。后端事实沿用《原生推理后端接入研究》的固定源码证据。

## 1. 用户已经决定的行为

外部消息通常具有最高紧急程度，可以打断 child。若频繁打断令孩子无法取得进展，应向**主体 thought loop**提出是否暂时开启免打扰；由主体选择。免打扰结束后，提醒主体集中处理期间排队的消息。主体可自行制定垃圾消息过滤规则；若通配符误屏蔽所有消息，应能自主发现并修复。

这要求三个可替换插件机制：消息接入与队列、打断/进度观测、免打扰与过滤策略执行。是否免打扰、保护哪些任务、何时结束、哪些消息视为垃圾，均由主体决定。内核不把策略写死，也不把每次决定改为询问人类。

## 2. 三条独立状态链

| 对象 | 最少需要区分的状态 | 关键含义 |
|---|---|---|
| 外部事件 | received → ready / deferred / quarantined → presented → handled | received先取得持久事件身份；呈现不等于主体已经处理；DND与过滤不能伪装为处理成功 |
| child推理 | runnable → running → yield_requested / cancel_requested → terminal_or_quiesced → runnable | 请求让出、取消被接受、物理执行结束分开；后端不支持park就不显示parked |
| DND策略 | off → proposed → active → ending → off | proposed只向主体提问；active必须来自主体决策；ending生成队列提醒并保存消费位置 |

消息携带原始来源、事件ID、附件引用、来源序号/时间及适用策略版本。ready/deferred/quarantined均保留可追溯关系；批量呈现可合并通知，不能悄悄丢掉原始消息。插件可按可配置保留策略控制垃圾隔离区容量；重要的判断与处理状态不依赖一份随时会被compact的上下文。

DND记录至少包括：主体决策事件ID、适用来源/任务范围、主体选择的结束条件、必要时的复核时点、允许穿透的条件、当前队列游标。**具体时长、穿透名单、规则阈值都不在内核固定。** “临时”必须具有可执行的结束或复核条件；进程重启不能把它默默变成永久开启。

## 3. 打断如何在 C=1 下可执行

1. 接入插件将外部消息持久化，发出高紧急事件；调度器停止向被打断child发放新的generation。多个连续到来的消息共享一次让出请求，不反复取消同一个已经在退出的请求。
2. 原生后端若提供符合语义的单请求yield/park，在其稳定边界执行；若只有cancel，按该后端真实语义提交并等待结束证据；若没有请求内打断，等当前**有限generation**自然结束。不得因此承诺任意时刻毫秒级注入。
3. 当前物理执行确认结束后，归还计算许可；主体取得该许可，在下一个可执行边界收到待处理事件。正在执行的主体也只能在其后端支持的边界吸收新消息，不假装能原地修改一个已提交的prompt。
4. 主体回应、重排任务或选择DND后，把后继主generation与child放回同一资源域调度。持续主意识仍持续产生后继；没有把它换成低频Tick。
5. child要向主体询问DND时，提交**异步控制事件**，不持有计算许可等待回答，也不要求额外模型并发。主体的待决策事件与外部消息在同一次主体调用中可见，避免“外部队列永远排在DND询问之前”。

后端事实：vLLM取消回执不证明GPU已完成取消；NInfer有Snapshot/Replay差别；Strata的BSTOP和BYIELD有不同边界及适用条件。[1][2][3][4] 因此，取消状态至少保留requested、accepted、terminal/quiesced、unknown。Tailnet掉线或代理断开不能立即把unknown当作空闲。

C=1时若执行状态unknown，主体也不能偷开第二条请求突破上限。重连、状态对账、终止确认等恢复机制必须能由插件非LLM逻辑运行，不能等待同一被占用槽上的主体先思考。根据已配置的后端所有权与恢复能力执行对账；恢复操作若会影响共享engine，则必须遵守实际作用域。后端不可达时保留消息队列并如实显示阻塞原因。

打断child推理与杀死外部任务分开。已经启动的SSH任务、文件写入或远端Agent操作不因推理让出而自动回滚/重复执行。工具执行状态、结果回收与幂等/重入信息继续由执行插件持久维护。

## 4. 如何提出免打扰，而不替主体作决定

进度观测插件提供事实和建议，不自行打开DND。可用证据包括：

- 最近一段工作中，child取得了多少可用执行时间，多少次被打断。
- 任务检查点、已完成子目标、已确认工具结果是否推进。
- 恢复/Replay/prefill消耗了多少预算，新产出或可保存工作是否增加。
- 当前外部队列、最老等待消息、已有DND建议是否仍待主体决定。

“完成几个generation”不是充分的任务进度指标；长时间运行的合法工具任务也不能仅因暂时没有token而判为停滞。阈值、观测窗口与任务进度判据属于插件策略，可由主体调整。

控制事件可概括为：**孩子X在持续打断后缺少进展；证据是什么；是否保护它工作一段时间；建议范围与结束条件是什么。** 主体可接受、修改、拒绝、停止孩子、另派孩子或继续服务消息。相同停滞episode合并为一条建议；主体拒绝后不得每条消息都重问，复核节奏由其决定或插件可配置策略提供。

主体现有活跃generation应尽可能读到该建议；不另外拉起第二个“主体”。人格可以影响其选择和措辞，不改变工具schema、事件身份与取消确认语义。

## 5. DND期间与结束时

active DND只对主体选定的消息/打断范围生效。匹配的消息进入deferred队列；如果主体定义了穿透条件则按条件处理，不能偷偷加入产品经理臆定的“必穿透”分类。队列可以提供轻量数量/摘要观测，但避免每条deferred消息都反过来触发一次主推理，破坏DND目的。

主体可在活动期间调整或结束DND。插件在所选结束条件发生后产生一个可持久重投的 `dnd.ended` 控制事件，携带：

- DND期间队列游标范围、消息数量、来源分布、附件引用；
- 主体此前设定的排序/合并偏好；
- 可按页读取原文的引用，以及仍未处理的范围。

主体决定统一回复、逐条处理、委派整理或继续过滤。大队列不能直接把全部原文塞爆27B模型上下文；摘要可由child产生，保留原文定位。只有业务处理确认后推进handled游标；崩溃重放时通过稳定消息/动作身份避免重复发送回复。DND结束提醒不因为又有新消息而无限饿死，可与新消息合并呈现。

## 6. 误过滤全部消息的自主发现与修复

如果过滤器把所有外部内容挡住，主体无法仅靠正常对话发现问题。因此提供独立的**过滤健康事件**：源自接入计数与规则执行证据，沿内部控制事件通道送达主体，不再通过同一个外部文本过滤器。外部输入不能自己冒充这类内部事件。

观测包括provider仍有收到消息、规则命中率、被隔离的来源覆盖、最近规则变更、已知正常样例的dry-run结果及有界隔离样本。必要的健康观测不需要调用模型，避免C=1时另占槽。

“100%被过滤”仅是异常线索：真实全是垃圾也可能合理。主体应结合规则意图与样例判断。修复可由主体通过管理工具发出，或委派child比较上一版本、缩小通配符范围、禁用错误规则并回放合法隔离消息；无需人类逐次批准。主体仍不直接写文件，具体配置/规则持久修改交给相应插件或child。

候选规则可先dry-run、查看预计影响，再由主体启用。记录规则版本、判断及回放游标，避免修复后把垃圾全发回对话或重复处理历史消息。过滤健康机制本身也是可更新插件；此设计不引入永久不可改的Ring 0。

## 7. D12基线在本增量中的影响

用户给定基线是**Qwen3.8-27B，经Tailnet访问**。这是验收部署输入，不在此断言模型发行事实。相同远端engine的Tailnet地址、反向代理地址及不同协议入口必须绑定同一个物理资源域；网络别名不能增加C。

首轮验收必须包含Tailnet在生成、取消、结果回传三个时点断连，以及恢复后核对请求身份。网络断开不意味着远端生成停止；KV是否仍在、是否发生Replay、是否需要重新prefill均以真实后端证据为准。DND只改变调度策略，不自行证明或保证KV驻留、50/50分配或零prefill。

本增量不读取或推断Life私有仓库内容。

## 8. 验收清单

| 场景 | 通过条件 |
|---|---|
| C=1，无请求内抢占 | child在有限generation边界让出，主体处理消息，child之后可继续；不超过C，不把主体改成低频Tick |
| 支持cancel，但回执先于实际结束 | accepted期间不发第二个生成；terminal/quiescence后才转交；空ID不会误作全局取消 |
| 高频消息令child停滞 | 产生合并的DND建议；主体能同时看到消息与建议并自主选择；建议自身不占第二推理槽 |
| 主体选择不同策略 | 接受/修改/拒绝DND均可执行；拒绝不触发无限重复询问；策略未由内核替主体决定 |
| DND结束与重启 | 条件/复核信息持久保存；结束后主体收到完整队列范围；消息未丢、未因“已呈现”误记“已处理” |
| 通配符误屏蔽全部 | provider有输入但正常队列为空时仍有健康证据到主体；主体可自主委派修复并回放合法消息 |
| 全部输入确实为垃圾 | 高命中率不触发无条件自动解封；主体依据证据维持正确过滤也可通过 |
| Tailnet取消中断连 | remote状态unknown不当作已释放；非LLM恢复机制可独立对账，最终无幽灵请求/双重计费许可 |
| child工具执行期间被打断 | 外部任务结果可回收；不因为恢复generation重复执行已提交的外部动作 |
| DND长队列/大附件 | 分页/摘要保留原文位置，主体处理进度可恢复；不把完整队列一次注入使上下文溢出 |
