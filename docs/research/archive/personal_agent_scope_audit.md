# 个人 Agent 最小框架定位与需求覆盖审查

审查时间：2026-10-23 Asia/Shanghai。依据：用户最新裁决、当前主稿 `agent_bot_spec_v0_1.md`、各研究补充。本文件为研究/规格建议，不改主稿、不进入开发。

## 1. 应写入产品定义的核心定位

“Pi 是面向 coding agent 的最小框架；我们要成为面向 personal agent 的最小框架。”此处是用户明确的产品定位，并非宣称 Pi 没有扩展到其他任务的能力。可以借鉴其小内核、可替换模型/工具、扩展和 session 机制，但产品中心必须是**一位连续的个人主体及其关系、生活事件、承诺与行动能力**。代码工程、SSH 工作位与浏览器是它能使用的工作环境之一。

小内核的含义是稳定且可替换的最小宿主契约；不意味着把个人 Agent 必需的语义交给互不关联的聊天脚本。联系人、来源/受众、连续人格、原始经历、主动意图、承诺与任务、委派及结果回灌需有共同协议，即使具体实现全为插件。能力包可拆装，身份与事件语义不能随便各做一套。

## 2. 从编码框架到个人框架，必须改变哪些中心对象

| 维度 | 本产品要求 | 规格不能退化成 |
|---|---|---|
| 生命周期 | 无人发任务也持续下一轮思考，唯一主体可恢复 | 每来一条消息启动一个 coding session，结束即消失 |
| 输入 | 人/群/课堂/通话/文件/网页/远端任务/自身意图进入统一有序主体输入 | 所有事件都伪装成单条用户 shell prompt |
| 核心关系 | person、平台身份、受众 scope、关系来历与置信度 | 用 cwd/repository ID 代替人与关系 |
| 记忆 | 原始经历、对话、事实、承诺、关系变化与引用 | 只有项目 README、代码检索和压缩摘要 |
| 自主工作 | 自选下一步，维持已承诺事项，主动联系、探索、维护自己 | 只有 cron 执行用户提前写好的命令 |
| 行为方式 | 主体思考/读存记忆/委派；执行能力在孩子和插件 | 主体默认获得 shell 和所有项目权限 |
| 对外连续性 | 同一人格跨渠道、媒介和节点；受众上下文分离 | 每个群一个会越长越不同的人格副本 |
| 可扩展性 | 原生 provider + Skills/MCP，任意层可候选自改并自动晋升 | 巨大固定工具清单，或永久不可改 rescue/core |
| UI | 当前关注、关系/会话、活动与结果、家园/节点、资源状态 | 以代码 diff 和终端日志作为全部产品主页 |

“已覆盖”指已有规格文本，不代表已实现。

| 同一人格与自主演化 | 主稿主体/人格部分；`remote_agent_spec.md` §1.1 | 最新已允许自改人格/主 system/内核/rescue。仍需一份当前生效人格、版本来历和唯一行动主体；不是每个渠道自行漂移 |
| 动态联系而非固定失败通知 | 主稿 §16；remote §6 | 真实可达性、偏好、情境、安静时间、权限范围驱动选择；跨渠道同一 decision ID；不能把一个人的账号误当另一个人 |

| 屏幕、视觉、鼠标键盘、浏览器 AX/DOM | remote §13，本轮新增 | 正式 ComputerUseProvider；native node/VNC/RDP/browser 可替换；截图证据、input lease 与人类接管不可省 |

| 真实持续个人生活/自维护 | 主稿 §5/§9；thought loop 补充 | 必须允许主动选目标与持续关注。具体项目研究可结束，主体不随其结束而停止 |
| 小内核、全插件、低资源节点 | 主稿 providers/部署；remote §9/§13 | 重型桌面、媒体、SDK companion 不驻留核心；独立安装和卸载；路由器可协调远端能力 |
| 任意组件自改与恢复 | remote §1.1/§13.6；主稿需更新旧措辞 | 候选 A/B 自动晋升，旧可启动闭包保留，状态兼容性验收；当前合同 gate 不等于代码永久冻结 |
| 唯一主体与多模态、多渠道并发 | 主稿消息/媒体；thought UI；remote §13.5 | 高优先事件不是第二主体，临时 worker 不是第二人格，视觉和语音也不能悄悄产生旁路自主 loop |
| 极致隐私与本地推理 | 主稿 ACL/broker；remote §8/§13.5 | 远端 cloud agent 是明确目的地和独立资源组；私密图像/音频/关系数据不随插件选择悄悄上云 |

## 4. 主稿重大矛盾/遗漏清单（未修改主稿）

1. 当前约 line 225 “主 system 硬性职责…不参与 Agent 自由改写”与最新 any-part selfrewrite 冲突。应改成可以修改实现/策略候选，激活必须满足当时有效的行为合同。不能让候选自行放宽 gate 再通过自身。
2. 当前约 line 134/227 “人格自动提升仍待裁决”已过时。已允许自主候选与自动晋升；主体连续性、当前合同和 A/B 仍约束实际激活。
3. 当前约 line 165/167 的 kernel/rescue 要明确是当前执行/恢复角色，而非永久不可改制品。保留一份可启动旧版本并验证迁移恢复才是恢复依据。旧根可能在之后由更合适旧版本替代，不要求无限保留所有旧内核。
4. Provider 列表约 line 173 缺少 ComputerUseProvider；完整环境约 line 639 不能将 Windows/macOS desktop 简化为 Linux 容器。正式能力与分阶段实现可分开表述。
5. 联系人部分已处理 identity，但 personal-agent 产品还需明确**关系与承诺的生活语义**：例如“答应某人下周主动回访”是有来源、受众、期限、完成证据的持续事项；不是只有工程任务。可复用 Task/Memory/Contact 协议，避免创建沉重专用核心。
6. 旧 `thought_ui_notes.md` Q4 关于人格是否自改是历史未决记录，现已被回答。最终问题清单不要再拿它追问；该笔记中的“人格不能覆盖协议”应理解为当前运行时约束，不能解释成协议实现永不可改。

## 5. 用于验收个人框架的三个跨能力场景

**一段关系而非一个项目：**某人昨天在 QQ 私聊说正在准备答辩，今天用已验证的飞书身份发语音求助。主体认出同一人，按可见范围忆起约定，委派搜索和整理；不因为账号相似自动合并，不把私聊内容带入公开群。事情完成后维持已授权的回访承诺。

**课堂与远程工作同时存在：**主体在旁听课堂，收到远端 omp 的 AskUserQuestion 和朋友的短消息。转写事件与提问进入同一主体序列，主体委派继续处理远端已授权事项、记课堂笔记并选择何时回复；完整工具能力存在，C=1 调度真实，音频未生成第二主体。

**自主成长仍是同一个它：**它注意到自己反复忘记回访，自主委派孩子改善记忆/联系策略，同时升级 ComputerUseProvider 与救援候选。验证后自动启用，保留原经历、承诺和可启动回退根。新版本收到已过期屏幕输入/旧 decision 回答时拒绝应用；用户看到行为改进和版本说明，不看到虚构“思想直播”。

以上三个场景与编程能力并列；能够完成 coding benchmark 或接入十种 IM 并不能单独证明 personal-agent 框架目标已完成。
