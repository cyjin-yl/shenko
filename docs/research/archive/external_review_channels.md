## 2. PTY Semantic Differ：值得做，但不应把显示解析等同问题理解

### 2.1 一手证据支持什么

`vt100` 当前公开文档显示版本 0.18.1，职责是解析终端字节流并提供渲染后内容的内存表示；示例中的 `contents_diff` 输出仍然包含终端控制序列。它提供屏幕状态/差分原语，**不是 Agent 问题识别器**。

来源：https://docs.rs/vt100/latest/vt100/ ，ref `turn106view3`。实际选用库还需针对目标 TUI 和 Unicode/重绘能力验收，不能因名称 vt100 就假定覆盖所有终端特性。

tmux 官方 control mode 提供文本协议、命令响应和异步通知，可经 SSH 使用；它是输入/输出传输与定位原语，不定义 AskUserQuestion、权限或任务完成语义。来源：https://github.com/tmux/tmux/wiki/Control-Mode ，ref `turn108view2`。

Claude Agent SDK 则已有结构化 `canUseTool` 路径处理工具审批与 `AskUserQuestion`，两类请求应分别处理。来源：https://code.claude.com/docs/en/agent-sdk/user-input ，ref `turn108view0`。OMP 的 RPC/ask 能力参见已核验 `remote_agent_spec.md` §2，而非改用正则覆盖它。

### 2.2 推荐处理链

原始 transport event → 终端解析/屏幕状态 → 版本化屏幕差分 → 特定 agent 版本的交互适配器 → `DecisionRequest` 候选 → 当前 seat 与授权核验 → 自主决定/联系用户 → 投递并确认问题已被消费。

保留有界原始字节或可恢复快照引用、cursor/screen revision、终端尺寸、模式、进程/seat/session 身份以及解析器版本。默认给模型看结构化变化和必要上下文，必要时可委派读取完整现场；不能只保留无法复核的“模型觉得现在是选择题”。

同一屏幕的重复动画、计时器和 spinner 可合并，但问题选项/默认值、错误、退出、目标进程变化、输入焦点改变不能被去噪丢掉。相同文字在不同 question epoch 是不同问题。

### 2.3 静默和 y/N 的反例

- 编译程序五分钟无输出，静默并不意味着正在等待许可。
- 文档或代码示例出现 `Continue? [y/N]`，它可能只是 scrollback 内容。
- CLI 已退出到 shell，延迟到达的 “y” 不是回答原问题。
- TUI 持续重绘同一问题，看起来一直活跃，静默检测反而永远不触发。
- 网络掉线造成没有新输出，不代表远端进程已暂停。

因此静默只是一种可调的观察触发信号，不能授予输入权限。结构化 bridge 不可用时，支持经过充分 live verification 的 tmux 兼容路径；低置信度先再观察、检查进程/版本或调用其他结构化能力，不强制每次问人，也不盲目自动按默认项。

远端 permission 事件不自动成为全局最高优先级：其来源、截止时间、被阻塞任务和既有委派决定优先级。否则一个远端 TUI 反复弹窗便能饿死整个本地 API。

## 3. 联系升级：让策略帮助主体，而非用计时器取代判断

“最近活跃渠道”有价值，但不能等同“最适合这条信息的渠道”。用户可能刚在公开群发言，但当前问题包含 SSH 主机名或私密记忆；也可能在开会、睡觉或明确希望某类事项只用异步消息。

建议 ContactPolicy 提供已验证目的地、最近活跃、近期成功送达、provider 可用性、时区/安静时间、敏感内容范围、任务期限、阻塞程度、用户历史偏好和长期授权。主体根据这些信号选择原渠道、私聊、可选电话或其他已接入方式；语气和节奏可受人格影响。

**“3 分钟未读”不能作为统一合同。** 没有可靠 read receipt 的 provider 只能知道已发送/已送达/未知；无人回复也不证明没有看见。3 分钟至多成为某个明确紧急场景的可配置策略参数，不能变成所有任务的默认电话升级。

电话能力本身需要 Telephony/Voice provider、已验证联系人和已有的联系授权；已有长期授权时无需逐次阻塞确认。不能因为能发送 IM 就假定能给对方拨电话，也不能因为用户“最近活跃”便扩张允许联系的人群。

每个待决问题共享 decision ID，各渠道投递留在 outbox，记录升级理由、时间、回执及不确定状态。已解决/取消/过期的问题撤销后续升级；其他渠道晚到答案按旧版本处理。用户无法联系时，主体继续其他可做任务，并选择等待/替代方案，而非固定报错或无限重拨。

## 4. PersonID：0.96 不是通用的身份概率

声纹与打字风格可以辅助认识人，适合作为自然演化联系人系统的一种可选 evidence provider。把不同模型的任意 score 都叫“置信 0.96”并自动合并身份，缺少校准依据。

例如 SpeechBrain 官方 speaker verification 接口返回 cosine score 和按 threshold 作出的预测；文档的分数定义不是“此人有多少概率是 owner”。这直接说明不能把一个相似度阈值无条件翻译成跨模型、跨麦克风、跨语言的账户归一保证。

来源：https://speechbrain.readthedocs.io/en/latest/API/speechbrain.inference.speaker.html ，ref `turn106view4`。这里不建议照抄其示例阈值；目标是指出 score 的语义必须由实际 provider 声明。

建议分三层：

1. **观察身份**：某平台稳定 ID、某音频片段 speaker、某次会话的显示名；原始来源不改写。
2. **Person 候选关联**：证据、识别模型/版本、分数语义、质量条件、最近验证时间，可由 Agent 自主记录和修正；允许 unknown、多候选、撤销与拆分。
3. **已验证账户/权限关联**：通过明确账户关联或其他可验证证明成立；管理员必须仍由人类明确登记，不能由声纹/文风算法升级。

同一人在感冒、换设备后可能不像自己；两个同事可能使用相同话术；录音回放、多人重叠或复制文本也可能与本人相似。因此可用推断支持称呼/候选记忆检索，但涉及跨域读取私密资料或 owner 权限时使用已验证主体，不靠固定分数放行。这个设计保留自然认识人的自由，不让错误猜测不可逆地污染历史和访问权限。

## 5. 语音热/温流：采纳工作分层，不采纳第二主体与固定课堂节律

### 5.1 可以采纳的部分

连续媒体不应每个 packet 都调用大模型。可区分快路径事件（用户直接提问、唤醒、打断、停止播音等）与背景整理（分段转写、话题边界、笔记、索引）。VAD/ASR/说话人识别、缓存及摘要作为可替换处理插件，各自受设备和推理资源预算约束。

温流可以在子 Agent 中聚合、整理并提供可检索证据；热流可以携带时间戳、当前请求、最近相关音频/转写引用和必要的历史提示。二者都进入同一个主体的输入模型，不产生两个长期人格。

按用户最新确认，连续主体必须持续获得媒体会话状态、已形成的语义事件和原文/原音频 handles，能主动关注并委派读取。聚合是减小输入噪声与推理负担，不能把课堂期间的全部输入截留在温流，三分钟到点才被动唤醒主体。保留输入序列与可追溯来源，不要求每个物理音频 packet 都作为一条 LLM 消息。

### 5.2 需要删除或改写的承诺

- **每 3 分钟摘要**：可以是可调批处理示例，不是默认固定节律。语义边界、直接提问、重要事实修订和截止时间可能需要更早更新；安静长段也可能适合更低频。
- **45 分钟主 loop 不介入**：若仅指不处理每个音频包，可以成立；若指主体被停用、不能关注课堂或主动委派，则与用户的持续思考要求冲突。
- **只给最近 30 秒**：可作为可调 ring buffer 起点，不能替代整段可追溯原音频/转写。用户可能问刚才二十分钟前讲过的条件，需按需检索和引用。
- **声纹/唤醒词直接 P0**：它是事件来源线索，不是管理员或无限抢占权。按已验证会话、事件类型、紧急度及资源策略赋权；重复唤醒合并，不能让背景电视让所有任务饥饿。
- **毫秒开口**：没有具体设备/模型/负载测量不能承诺语义回答在毫秒内生成。检测、排队、取消、ASR、检索、prefill、生成、TTS、网络都可能影响时延；一个本地提示音/录制短确认的快速播放，不等于主 Agent 已理解并回答。

### 5.3 更好的可验收合同

记录声音进入、语音事件形成、主体接收、推理获准、首个语义文本、首段音频和播放中断的时间；在声明设备/模型/C=1/负载下报告 p50/p95 和超时行为。不会中途插入新 prompt 的后端，在安全边界注入或经已配置取消/确认策略处理；不另起第二主 loop 来隐藏等待。

保留 partial/final transcript 修订、原始片段引用与受众范围；早期转写把“不可以”错成“可以”时，不应造成重复或相反的外部承诺。主体在旁听中依然可以让子 Agent 搜索概念、检查远端 seat、计算和整理资料。

## 6. JIT help wrapper：降低知识负担，不制造隐式执行

价值在于：小模型不需要记住所有工具版本与 CLI 细节，使用前按需取得可靠帮助。应优先已有 schema、安装包内文档、已注册 recipe 和已验证的帮助摘要。

不采纳“所有非高频白名单命令先自动执行 `cmd --help`/`man`”：

- `--help` 是工具约定，不是未知可执行程序的无副作用执行保证。
- shell pipeline、函数、alias、SSH 内的远端命令、带子命令的 CLI 不存在通用安全的字符串拼接方法。
- `man` 的版本/主机来源可能与要运行的 binary 不同；必须明确文档对应版本。
- 每次重复探测浪费启动时间、上下文与 prefill，且帮助本身也可能极长。

推荐 `CapabilityHelpProvider`：解析确切工具和子命令，优先缓存静态资料；必要时由已授权 worker 进行有时限、输出上限和环境约束的帮助探测，按 executable/package digest、版本、子命令和 locale 缓存。探测依然是执行能力，不暴露给禁止直接 exec 的主循环。失败时返回真实“不支持/未知”，而不是自动尝试更多可能产生动作的参数。

此项与 `research_plugin_cognition.md` 的渐进工具发现/教学机制衔接；没有任何证据支持一个固定 wrapper 能让所有未知 CLI 都自动可用。

## 8. 竞品：无人值守不是尚无人实现的空白

附件 §2.7 与 SPEC 11 把 dots/Duet/Muse 统一描述为“用户在场审批/简报”。这一表述将“某些动作需批准”误推为“后台工作要求用户在场”，与公开一手资料冲突。

| Claude Duet | 2026-10-21 官方明确离开后继续，自己的 VM，不要求用户电脑/手机开机 | 发送、支付、签署、删除等要求审批；后台监测并非持续无限推理 |
| Meta Muse | 2026-09-08 技术文明确 unattended、后台、subagents、自建工具和自改 | Sentinel 与 runtime 分离，外部动作受其许可体系约束 |

本产品可明确的设计目标差异：用户拥有的本地部署与模型选择、任意层可候选自改、可恢复 WASM 家园、唯一持续主体、API/KV 的共享资源治理、开放对话但手动管理员、可安装远端 agent seat/媒体/桌面能力、按人格与情境动态联系。这些须逐项实现和验收；“更自主”不应只靠宣传语成立。

## 9. 附件中的授权与自改建议，不能覆盖已确定需求

按目标/动作/任务设长期授权范围有价值；它可以减少重复提问，并区分开放聊天与敏感能力。但不直接导入附件中所有默认表格：尤其“内核/宪法 self-rewrite 必须用户审批”已被最新用户裁决否定。

本产品允许 kernel/rescue/调度器/人格等任何层候选自动验收和激活，保留旧可启动闭包。用户当前有效的行为合同需要被新实现满足；合同与实现可替换的区别，不能偷换成永久不可修改的软件模块。

用户现已明确排除永久 Ring0 与用低频 tick 替代主体思考。50/50 KV 也不固化进 kernel：它保留为必须支持的可选使用场景，实际可由可换 scheduler/plugin 采用 auto 或主体偏好策略；媒体热/温流不能借机重新引入上述已排除的设计。

附件还称“所有 ask 在用户不在时，低风险就自主选择”。这混淆了两种 ask：

- 若只是实现选择/补充信息，在已委派范围内可由 Agent 自主决定。
- 若既有策略明确把某项新授权保留给人类，不能因为没有回复或认为低风险就自行授予权限。

可以预先给 agent 足够范围的代理决策权，之后无需逐次 ask；不能既声明必须人类批准，又在运行时静默绕过该声明。`notify` 同样应区别审计记录与打扰用户：每次普通文件写入都发通知会破坏用户要求的默默维护。

## 10. 本轮建议增加的针对性验收

1. 终端历史含 y/N 示例、进程静默和 TUI 连续重绘，均不被误判为可直接确认的当前 permission。
2. 远端问题刚被人类回答，延迟 semantic diff 到达后不在 shell 输入旧答案。
3. 最近活跃渠道为公开群，私密待决事项选择已允许私聊；无 read receipt 时不伪造“未读”。
4. 普通问题等了三分钟不自动电话；真正有期限的问题依长期授权和情境可主动升级，问题解决即停止其他渠道升级。
5. 声纹高分但平台账号未关联，不获得 owner 私密记忆/管理权限；错误 person 候选可拆分，历史原始身份仍保留。
6. 45 分钟课堂期间主体始终可接收新提问、委派其他工具、查询此前内容；没有固定三分钟禁入窗口。
7. C=1 正在后台推理时收到语音打断，报告真实排队/取消/首段音频延迟，不另开隐形推理流冒充即时。
8. 新 CLI 帮助获取命中确切版本缓存；未知可执行程序不会因 `--help` 标签绕过执行能力约束。
9. Proto 主线升级后保持键盘焦点、已有表单草稿与 action identity；原生 UI 不支持时渠道 fallback 可操作。
10. kernel/rescue 候选通过当前合同自动晋升，失败可回退；没有附加“内核更新永远必须人工”阻塞条件。

本轮没有执行真实远端输入、拨号、身份合并、未知命令探测、组件安装或代码开发。所有固定数字（0.96、3 分钟、30 秒、毫秒）都应视作待评估配置/主张，而非未经测量的产品保证。
