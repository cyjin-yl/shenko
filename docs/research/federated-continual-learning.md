# Shenko 持续学习与联邦学习：研究储备

日期：2026-11-22（Asia/Shanghai）。源码核查基线：[`main@f3fa6f4d`](https://github.com/cyjin-yl/shenko/tree/f3fa6f4d8bf22cfd2baf490d9c3a08bd39af4d42)。本文是非规范研究笔记与离线实验计划；现行行为以[领域合同](../INDEX.md)为准。

用户本次请求原文：

> 为shenko做一些联邦学习的积累？因为实际上如果continuous learning实现了说不定会用到的

这次积累包括文献依据、源码边界、学习工件草案、可重复的聚合代数探针和后续实验顺序。没有新增参数训练能力，没有训练用户数据，也没有测得 Shenko 的学习收益。文中的方法选择、字段与推进条件是工程建议，不是用户已经选定的产品合同。

## 1. 研究判断

**先积累可验证的经历、可复现的训练输入和可比较、可回退的候选，再研究节点之间怎样共同学习。** 联邦学习可以成为学习插件的一种实现，不应成为主体一致性或持续思考的前提。

Shenko 的特征是同一主体跨设备延续，认知与经历应同步，provider、凭据、本地权重和实际能力可能不同。[节点合同](../specs/nodes.md)因此没有天然满足经典联邦学习“各客户端保有不同私有数据、共同训练一个兼容模型”的设定。如果允许使用的经历已经能汇集到可信计算节点，**集中训练后分发产物必须作为对照**。若问题只是将算力分散在多台机器，还应比较普通分布式训练的代价；多机器本身不是选择 FL 的理由。这是对本项目的工程推断；FedAvg 的原始问题与算法见[文献 R1](#references)。

| 层次 | 学到什么 | 对 Shenko 的含义 |
| --- | --- | --- |
| 记忆与检索 | 可追溯的经历、事实和修订 | 新事实可先通过检索生效，不必修改参数 |
| 非参数适应 | awareness、Skill、上下文方法、工具使用方法 | 当前已有可安装、可撤回及有限行为对照机制 |
| 参数持续学习 | 通过一段时间的新数据更新模型或 adapter | 需要独立证明泛化、旧能力保留、训练与部署可恢复 |
| 联邦协作 | 各端本地学习后交换更新或可迁移知识 | 是参数/知识协作方式之一，不自动解决数据质量和遗忘 |

持续学习也可以按有边界的批次在后台发生；不要求每条消息后立即反向传播。发生过的事实、当前理解、训练产物、实际加载的模型，是四种不同状态。

## 3. 哪些场景值得采用联邦方法

| 场景 | 优先研究的方案 | 决策依据 |
| --- | --- | --- |
| 同一主体的数据可汇集、一个节点适合训练 | 集中 replay + LoRA，再按能力部署 | 作为最直接的参数学习基线，先证明值得训练 |
| 数据有实际驻留约束，且节点能训练同一有效基座 | 同基座联邦 LoRA | 比较受相同约束的各端独立学习；不要求胜过不可合法运行的集中方案 |
| 节点常离线、不同时间获得新经历 | 本地候选 + 有版本依据的延迟聚合 | 先测离线适应的收益，再引入异步算法；断网不赋予旧候选全局发布权 |
| 大小模型、模型系列或 tokenizer 不同 | 经验证的经验迁移、文本/输出蒸馏 | 参数坐标不兼容时不能直接平均；logits 需要对齐，文本 API 不等于 logits API |
| 只有远端推理 API、没有训练接口 | 教师输出或工具轨迹供可训练学生使用 | 不能声称把 LoRA 回传给该 provider 就能改其权重；还需核对实际接口和数据使用条件 |
| 未来与其他独立主体合作 | 单独研究共享范围、投毒及聚合隐私 | 不是本次默认范围；同一主体节点加入不自动授权跨主体数据交换 |

节点专长可以表现为共享能力加局部 adapter，但不据此分裂人格或身份。借鉴 Ditto 的个性化思想需要重新定义 Shenko 的任务目标，不能直接搬用“每个客户端是一个用户”的假设。[R3](#references)

## 4. 三种可迁移材料

建议先让学习插件能清楚描述自己消耗和产生的材料，再选框架。下面是研究分类，不是新增内核消息枚举。

| 材料 | 能做什么 | 不能推导什么 |
| --- | --- | --- |
| 有出处和结果证据的经历 | 检索、集中训练、回放、工具策略学习 | assistant 自称成功不等于正确示范；同一轨迹的复述不是独立验证 |
| 兼容的参数/adapter 更新 | 在共同参数坐标上做聚合 | 模型名称相同、形状相同或都叫 LoRA，不足以证明兼容 |
| 蒸馏输入与教师输出 | 将不同模型的可验证行为迁移给学生 | 不能保证学生学会教师推理能力，也不能把缺失概率补成真实 logits |

FedMKT 研究大小模型的双向迁移和 token 对齐，适合作为异构路线的参考；本文更轻量的“先保存通过结果验证的文本/工具轨迹”是工程建议，不是 FedMKT 的等价复现。[R8](#references)

易变化的事实、待履行承诺和权限事实仍由可追溯记忆与实际系统承担。把某条经历用于训练，不会使模型参数成为账本真相源。删除检索条目也不代表参数已经遗忘；若训练材料被撤回，要追踪受影响候选，重新训练或采用经验证的遗忘方法，不能只删 replay 文件就声称完成 unlearning。

## 5. LoRA 聚合先把数学定义写对

### 5.1 聚合的对象是有效更新

在同一共同参考权重下，客户端有效更新记为：

$$
\Delta W_i = s_i B_i A_i,\qquad
\Delta W = \sum_i p_i s_i B_i A_i,\qquad
p_i\geq 0,\quad\sum_i p_i=1.
$$

`s_i` 是实际 scaling，包括具体实现如何解释 alpha 与 rank。即使先把 scaling 正确吸入 `B`，分别平均因子一般仍得到不同结果：

$$
\left(\sum_i p_i s_i B_i\right)\left(\sum_j p_j A_j\right)
=\sum_{i,j}p_i p_j s_i B_i A_j.
$$

额外交叉项和平方权重不是目标更新。FLoRA 讨论了这个问题，并使用 stacking；FlexLoRA 研究聚合后按资源约束通过 SVD 分配 rank；FedEx-LoRA 通过保留聚合误差残差实现另一种精确聚合。[R5–R7](#references)

反例否定的是“因子平均等于有效权重平均”。若某算法明确选择因子空间中的优化目标，不能仅凭不等式就判它无效，仍需比较任务效果。

一种直接的精确表示是：

$$
B_*=[p_1s_1B_1\ \cdots\ p_ns_nB_n],\qquad
A_*=\begin{bmatrix} A_1\\\vdots\\A_n\end{bmatrix},\qquad
B_*A_*=\Delta W.
$$

这里的精确仅指实数代数上的有效更新相等；不代表没有浮点误差、通信开销或能力回归。stacking 的表示 rank 为各端 rank 之和，压回固定 rank 通常有近似误差，应单独记录误差与任务结果。小矩阵探针会物化完整矩阵用于独立核验，不是生产大模型的内存实现建议。

也有成立的受限情况：所有客户端共用且冻结同一个 `A`，把各自 scaling 吸入 `B`，则平均 `B` 后再乘 `A` 等于平均有效更新。这个代数事实不说明该受限训练方法与完整 LoRA 有同样的表达能力或效果。

### 5.2 一个可复现的反例

本次构造的反例令两个客户端的因子互为相反数：`B₂ = −B₁`、`A₂ = −A₁`。两者有效更新完全相同；等权平均应保留原更新。但分别平均因子会把两个因子都变成零，最终更新也为零。这个例子只需精确有理数，不需要 GPU 或模型数据。

[探针脚本](../../scripts/probe_federated_lora.py)包含四个实例：普通交叉项、上述等价因子抵消、不同 rank/权重/scaling 的 stacking，以及共享冻结 `A` 的受限正确情况。每个实例保留具体输入、手算期望、直接乘积求和和 stacking 结果。

运行方式：

```bash
python3 scripts/probe_federated_lora.py
python3 scripts/probe_federated_lora.py --output /tmp/shenko-federated-lora.json
```

固定研究基线的原始输出保存在[代数探针回执](../evidence/federated-lora-algebra-20261122.json)。这是 `algebra_only` 证据；未训练模型，未验证分布式协议、隐私、SVD 压缩、收敛或 agent 效果。

### 5.3 兼容性不只比较模型名称

未来进入参数实验时，需要固定共同参考的实际权重指纹、目标 tensor 名称/形状/坐标、adapter 类型/实际 scaling、tokenizer/词表、模板、量化与精度、父候选版本。不同量化基座不能未经验证当作同一有效权重。

更新语义也要明确：上传的是相对共同参考的完整 adapter，还是相对本轮父候选的增量。不能把完整 adapter 当成新 delta 重复加到父版本。FedEx-LoRA 若把残差合入基座，还要把残差所定义的有效基座纳入后续版本身份；“最初 pretrained 文件没变”不足以描述当前模型。[R7](#references)

具体说，若本轮客户端终值为 `W_i = W_t + δ_i`，则目标是 `W_next = W_t + Σ p_i δ_i`；若上传的是相对固定 `W_0` 的完整 adapter `Δ_i`，则目标是 `W_next = W_0 + Σ p_i Δ_i`。两种记法的参考不同，不能混用。两个 LoRA 乘积之差也未必能用原 rank 的单个乘积表示，更新编码不能未经验证就减去 A/B 因子冒充 `δ_i`。

**异构 rank 不等于异构基座。** 不同基座可能需要专门的对齐或知识迁移方法；本研究不声称所有异构模型都无法共享知识，只排除未经证明的直接参数平均。

## 6. 先保留哪些数据和工件

下面是插件侧的记录草案，尚未注册为公开 API 或生产 schema。优先引用现有不可变对象，不复制原文或新建第二份真相源。可以组合成一个研究 manifest；不要求每行都拥有进程、数据库或子插件。

| 记录 | 建议内容 | Why |
| --- | --- | --- |
| 经历及其标签 | 全局 episode/event 身份、原文/动作/回执引用、节点与环境、模型/工具版本、验证器及标签来源 | 能分辨客观成功、用户纠正、模型自评、失败、未知；保留污染与误标的调查路径 |
| 数据集快照 | 来源谱系/内容摘要、抽取代码、资格条件、时间边界、去重组、train/dev/test 分组、采样权重、replay 预算 | 保证同一经历的多副本不重复计权，未来信息和跨节点副本不泄漏到留出集 |
| 学习运行 | 输入 manifest、共同基座/父候选、训练代码与环境、配置、seed、实际 token/step、资源使用、checkpoint/optimizer/RNG 引用、失败回执 | 可重现与恢复；“计划训练 100 步”和“实际完成 100 步”分开 |
| 本地更新 | 唯一 update 身份、内容摘要、父版本/轮次、delta 或完整 adapter 语义、tensor/scaling 描述、实际唯一训练样本覆盖 | 同一次训练的重发不重复聚合；同内容不自动代表同一个合法训练事件 |
| 聚合候选 | 输入更新的有序清单、去重决议、权重/算法版本、候选摘要、压缩方法与误差、兼容性结果 | 可以解释候选来自何处，避免丢失父版本或偷偷引入旧更新 |
| 评估与激活 | 独立 rubric/测试集摘要、全量计划槽及失败、旧/新模型组合、实际加载 readback、回退目标与效果回执 | 产物存在、评估通过、实例实际使用是不同事实 |

同一经历同步到三台设备，仍是一条来源。对共享数据按来源组分配本轮样本，或者采用明确的重叠修正采样；不能直接用三个副本的 `n_i` 扩大权重。训练去重和统计独立性也不同：不同经历可能来自同一任务会话，应以会话/任务族分组评估置信区间。[记忆的个性化与反思合同](../specs/memory.md#spec-45-12)已经要求多模型转述不算独立验证。

失败轨迹值得保存，但应与正确示范、纠正、偏好对分别标注。可验证的最终状态也未必证明整个过程正确：重复副作用、越过实际权限或用错目标等过程条件须单独核验。训练资格与评价规则由可替换学习方法拥有；文本内容本身不增加权限。

## 7. 分布式语义及后台执行

这里提出将来的实施约束，没有在本次实现状态机。

1. **训练者、聚合者、发布者分开。** 聚合是有限执行角色，可以被委派；沿用主体/分支的现有写入权威，避免再造平行的全局 leader。参数优化的收敛不等于日志一致性。[R9–R10](#references)
2. **每次更新有来源身份和父版本。** 同 update 身份同内容重复提交是重试；同身份不同内容是冲突。两个独立训练运行即使偶然产出相同字节，也要按数据和运行身份判断，不能只靠文件 hash 混为一条。
3. **先做固定父版本的同步实验，再研究 stale 更新。** 迟到、离线训练与重连先保留为候选；其基座、任务范围、数据时间与当前版本都可审计。允许多旧、是否重训或蒸馏由具体算法决定。FedBuff 是异步优化参考，不是现成的恰好一次提交或恢复协议。[R9](#references)
4. **原始经历合并和参数候选合并独立处理。** 分区可以留下不同经历和候选；重连不按文件最后修改时间、节点数量或“谁模型更大”直接覆盖生产模型。先恢复事实，再按适用算法形成新候选。
5. **训练是有界后台任务。** 将来通过现有 capability/hook 与耐久任务接入；即时消息和在线推理的实际资源需求优先。训练暂停/终止、显存释放、checkpoint 恢复需要真实验证，已有推理 `ResourceDomain` 不能当作训练抢占已实现的证据。
6. **封存过的请求保留原模型绑定。** 新候选激活不能改变在途请求所用的基座/adapter/template/量化；切换与恢复要在现有边界上验证。回滚整个实际模型组合，继续保留切换之后发生的事实及未决效果。

上述工作应服从[内核插件边界](../specs/kernel.md#kernel-7)、[后台修改与即时消息优先](../specs/subject-runtime.md#background-self-modification-and-interactive-ingress--2026-11-17)及[自更新合同](../specs/self-update.md)。它们是可复用的要求，不是模型部署已经完成的证明。论文中的去中心化优化不要求 Shenko 改变连通域内的主体主导权。

## 8. 最小学习实验：先证明收益，再证明协作价值

建议先在单机模拟三个逻辑节点、三个时间窗；这是探索规模，不是生产节点数量限制。优先用公开/合成、可执行验证的工具选择和参数填写任务，以及按上下文应用偏好的任务。先使用能在实际预算内训练的学生模型；小模型结果不能替代仓库参考模型与真实主体路径的后续验收。

### 8.1 实验臂

| 臂 | 方法 | 回答的问题 |
| --- | --- | --- |
| A | 冻结模型，不加入新经历 | 初始能力 |
| B | 冻结模型 + 检索已验证新经历 | 当前记忆机制已经能得到多少收益 |
| C | 集中顺序 LoRA，无 replay | 遗忘诊断 |
| D | 集中 LoRA + 有限 replay | 主要参数学习基线，相对 B 是否有价值 |
| E | 每节点独立 LoRA + 相同 replay 预算 | 没有协作时的本地适应 |
| F | 同有效基座联邦 LoRA + 相同 replay 预算 | 在明确数据/连接约束下，协作是否优于 E |

先运行 A/B/C/D；如果 D 没有任务收益或延迟/成本价值，先改进数据与学习目标，不默认扩大到 F。若数据确实不能集中，D 仅在许可的合成/公开对照中提供参考；不能为实验绕过数据边界，也不能把这个参考上限当作 F 必须击败的可部署方案。

通过基础实验后再加入共享/局部 adapter、异构学生蒸馏，以及 SCAFFOLD 等 drift 对照，避免首轮同时改变算法、模型、任务和资源。FedWeIT 对选择性迁移与任务干扰有启发，DER 支持将 replay 作为有竞争力的基线；原始视觉实验不能直接证明 agent 收益。[R2、R4、R12](#references)

### 8.2 公平比较与隔离

- C–F 固定基座、tokenizer、模板、工具协议、推理配置、优化器设置、全局训练 token 总预算和有效 batch 定义。D–F 固定所有节点合计的 replay 内存/样本预算与 token 份额，并报告每节点分配；C 的 replay 份额为零。显式列出 C/D 的新样本曝光与旧样本回放分配：总 token 预算相同不代表新样本曝光也相同。若加检索，采用相同检索配置；否则把检索因素明确单列。
- 同时报告唯一经历覆盖、总曝光次数、训练 token、计算/墙钟/显存和实际通信字节。固定全局 token 预算不等于固定墙钟预算，两个比较口径分别呈现。
- 按来源事件组、会话/任务族和时间切分数据；同一源的摘要、翻译、教师改写和另一节点副本继承同一分组。开发集用于调参，最终测试集固定且不进入教师构造或 replay。
- 明确节点间 non-IID 分布和时间漂移。首轮可用固定三个 seed 探索，保留每次结果；这不是足够统计功效的承诺。
- 隔离每个臂的模型/adapter、检索状态、工具环境和副作用。未知的外部执行先对账，禁止拿真实用户任务做不可控重复试验。

### 8.3 看哪些结果

主要结果是留出任务完成率、重复可靠性、旧能力保留与资源代价。任务成功以真实工具/文件/数据库状态及过程不变量核验，不把模型自评当唯一标签。借鉴 τ-bench 的 `pass^k` 测重复都成功的可靠性，与“多次至少一次成功”的 `pass@k` 区分。[R14](#references)

令 `S[t,j]` 为第 t 个学习阶段后在固定任务组 j 上的成功率，保存整张阶段—任务矩阵。受控实验显式记录每组首次学习后的阶段 `t_j`；对最后阶段之前已学习的非空组集合 `J = {j : t_j < T}`，借鉴 GEM 的后向迁移思想定义本研究的分组变化指标：

$$
\operatorname{BWT}_{\mathrm{group}}=\frac{1}{|J|}\sum_{j\in J}(S[T,j]-S[t_j,j]).
$$

若恰好第 j 阶段首次学习第 j 组，则 `t_j=j`，得到常见的顺序任务公式；任意多节点时间流不能默认符合这个顺序。没有清楚引入边界时直接报告完整矩阵与固定旧组的保留率，标注 BWT 不适用。负 BWT 表示后续学习后旧组表现下降；同时报告逐组历史最佳到当前的差值、最弱任务组/节点结果与泛化任务，防止平均收益掩盖某项旧能力退化。这里是将分类评测思想迁移为 agent 成功率，不是已验证的新统计保证。[R11](#references)

延续[现有行为实验](../specs/cognition-units.md#measuring-a-unit-the-finite-sandbox-comparison)对未知结果的要求：所有计划槽、未启动槽、provider/验证器/清理失败分别记录，报告 scored coverage 和保守效果范围；不能只丢弃失败后报告成功率。差异与不确定范围重叠时为 `inconclusive`。任务组内重复与跨节点副本不是独立样本，应按组评估不确定性。

需要更多重复时，理由应是缩小具体不确定性，不是追求固定测试数量。最终端到端比较要走实际 Store、subject、provider wire 和 parser，记录精确模型与配置，使用冻结的留出任务；本次代数探针不替代这一步。

## 9. 隐私与错误传播的研究边界

不传原文不能自动推出隐私保证。DLG 展示了特定条件下的梯度反演；安全聚合主要隐藏单个贡献，不能自动证明最终模型不泄漏、输入更新无投毒或训练标签正确。[R13、R15](#references)

对同一主体的可信设备，先写清真实数据去向、受限材料和凭据边界。若未来跨独立主体，才具体定义攻击者、串谋/掉线阈值、安全聚合与差分隐私的邻接关系、裁剪及累计预算。同一用户的三台设备不是三个独立隐私用户；用设备数替代用户数会改变保证。单纯加噪声没有建立 DP 证明。

签名或内容哈希只帮助确认来源和完整性，不证明更新有用。应保存可定位的训练出处和独立留出评估，避免把模型自己生成、自己认可的错误循环放大到所有节点。此处描述学习设计中的具体风险，不新增内核静态禁令或逐次人工审批。

## 10. 后续清单与退出条件

- [x] **源码与领域合同核对**：确认已有认知学习、推理和恢复机制的实际边界。
- [x] **文献与采用边界**：整理主要一手来源，区分研究结论与 Shenko 工程推断。
- [x] **离线代数准备**：提供四个精确有理数实例及原始回执，复核 LoRA 聚合陷阱。
- [x] **实验与工件草案**：定义对照、数据谱系、候选版本和观察指标，尚未注册生产 API。
- [ ] 学习数据导出：从授权经历形成可复查快照，证明跨节点去重和留出隔离。
- [ ] 单节点学习实验：完成 A/B/C/D，记录收益、遗忘、不确定性与成本；不支持时回到数据/目标改进。
- [ ] 联邦仿真：完成 E/F，触发 non-IID 与时间漂移；只有在明确约束下改善效果或成本，才进入真实节点实验。
- [ ] 更新/恢复机制：验证重复投递、相同身份不同内容、过期父版本、聚合者重启和候选加载失败；保留原始失败。
- [ ] 模型部署：验证后台资源让步、精确加载 readback、在途旧绑定、重启与完整模型组合回退。
- [ ] 异构迁移：分别比较文本轨迹蒸馏与能实际取得并对齐的 logits 路线；记录学生收益和教师成本。
- [ ] 真实多节点与长期观察：在实际设备/连接/模型条件下重复验证，不把单机仿真升级为运行验收。

第一版实施可用独立研究 runner 调用训练库；选框架前先确定数据、模型、资源和评价目标，不将某个 FL 框架提前引入 Shenko 本体依赖。将来需要产品能力时再经唯一插件生命周期接入。上述未完成项是研究路线，不因此暂停当前日用闭环和已有交付工作。
