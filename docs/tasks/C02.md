## 2026-10-27 语义等待切片（PR82，完整 C02 仍开放）

原先 `active_wait` 没有设置入口，且任何新事件都会清空它。本切片以主体实际输出的等待
控制形成 S1 `policy_intents`；同一事务保存等待记录、处置、回执和唯一后继，不设第二个
waiter，也不将主体改成 child sleep。正常资源可用时，原有串行主循环继续请求同一模型；
新事件只是提交给模型的上下文，不由框架自动判定等待条件是否成立。

当前协议：`[wait]` 指定语义条件和 1–600 秒上限；`[wait:continue]` 与 `[wait:end]`
自动绑定本轮冻结的等待，不要求模型复制 UUID。`[wait:replace]` 明确改变关注时在一个
S1 中结束旧等待并开始新条件；新截止时间是所请求截止与旧截止的较早者，不能用改写
条件或换 ID 延长原上限。相同条件的替换被拒绝，其他无效／迟到动作留下 typed 回执，
不丢同一 S1 的有效处置和后继。等待意图、原始模型输出和回执各有真实持久来源；等待
不是外部工具调用，不在原始会话里伪造 `tool_call` / `Unknown`。

等待的原始条件、开始／截止时间、上下文引用、provider binding 摘要和时钟观察高水位
持久保存并随认知快照复制。新 S0 schema 10 将等待与当前 provider binding 冻结，Store
同时核对来源；重开时绑定变化不会静默换模型。期间时钟回拨或本进程内单调时间到期会
使等待失效；重启后保留原始 deadline，不从恢复时重新计时。provider 的可变别名仍不能
证明背后权重未改变。旧 schema 8／9 的在途请求需要显式迁移／对账，不能原样交给新
parser 假装已兼容；旧 schema 4 的 native child 决定保留读取。尚未证明断电期间不可观测
的时钟回拨、网络分区合流或语义等价改写跨独立新决定的完整防续期。

真实模型使用用户指定的 Coder 390（Qwen3.8 后训练，NVFP4-W4A16）。旧协议 0/6 有
持久开始；第一候选开始 6/6、限定结果后原等待结束 4/6。第二候选 7/9 完整生命周期，
包含一个在途模型结果 unknown 的超时。第三候选严格生命周期 8/9，但留出场景一次把
背景纳入原条件并通过 replacement 让截止延后 52.09 秒；该失败促成本切片的继承截止
修复，不计为通过。

固定候选 `f4217db2e148dec68c5811270f864d8f4a5d6e26` 随后在真实 CLI/Store/Coder 390
沙箱以三个场景各运行三次：完整生命周期 **8/9（88.9%）**；留出邀请场景 **3/3**，
渲染 **3/3**，下载 **2/3**。未通过的一次是在已有等待时模型仍输出 start，S1 如实
拒绝；不将它算作已开始。九次中没有观察到续期，其中一次真实 replacement 的新截止
不晚于原截止。两个 start 路径（直接切换或显式结束后再开始）分别记账；本批没有
将后者伪记为直接成功。输入、原始输出、S1 回执与失败记录位置及摘要见
[本地语义等待证据](../evidence/c02-semantic-wait-20261027.json)。这不是每个场景均达到
85% 的证明，也不等于完整 RT16 或 C02 已通过。

对 `f4217db` 的既有回复协议回归发现 Coder 390 私聊回复 **6/8**，低于 85%；保存记忆与
空闲续思各 **8/8**。原因是提示词同时允许“要说的话直接写”和要求回复控制行；普通正文
可显示在系统时间线，但并不会发送 QQ 消息。`8b584174d3c424fd728f095d1a3983e12629578d`
澄清这个边界后，同一 harness 的回复／记忆／空闲均 **8/8**。该源码随后以相同三个
真实沙箱场景复测语义等待：**9/9** 完整生命周期、各场景 **3/3**、未观察到跨 ID
期限延长；本批没有出现 replacement，真实 capped replacement 的证据仍以前一批为准。
两批失败与原文保留，短场景和离线回归不证明长期运行或完整 C02。
