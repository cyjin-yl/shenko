### 候选切片：WASI REPL 会话合同、执行与 R0 恢复（`shenko-repl`）

新 crate `crates/shenko-repl` 实现 §19/§19.1 的 REPLProvider 合同与 WASI
preview1 后端（base `5959e455`，衔接 #103 的 WASI command IO）：

- `contract.rs`：`ReplProvider`/`ReplSession`（create/execute/inspect/
  checkpoint/restore/fork/cancel/reset/install_dependencies/dispose）、
  `ReplRuntime`（CPythonWasi/Pyodide/NodeWasm/BunWasm/JsWasm/Other 真实
  runtime 区分）、`CellKind`（Pure/DeclaredEffect/Unknown 重放边界）、
  `RecoveryLevel`（R0/R1/R2）。会话绑定 task/worker/scope、runtime/ABI、
  environment_generation、依赖锁、资源限制（当前如实 `enforced:false`）。
- `kernel.rs`：`KernelProfile` 把解释器绑定到 `ModuleSource::ModulePath`，
  create 时记 blake3，每个 cell 重读重验，模块被替换即拒绝执行
  （`REPL_KERNEL_UNAVAILABLE`），不悄悄换 runtime。`named_targets()` 如实
  报告：python-wasi、quickjs-wasm 可绑定；node-wasm、bun-wasm、pyodide 为
  具名不可用，不被 QuickJS/宿主 Node 冒充（R079–R081 边界）。
- `session.rs`：`WasiReplProvider`/`WasiReplSession` 在 `shenko-wasm` 上
  真实执行：每个 cell 一个真实 preview1 guest 进程，argv/env 精确传递，
  stdin 绑定已持久化的 cell 源码文件，stdout/stderr 落到独立文件并只回
  有限预览（blake3+截断标记）。guest 通过 `/home` 内声明的 state file
  跨 cell 进程保持解释器状态（`KernelProfile::persistence`）。
- `journal.rs`：宿主侧 JSONL journal（fsync）+ 每 cell 源码/输出文件；
  extra preopen 与会话私有目录不得重叠。输出文件及其目录先同步，再
  发布 cell 记录；fork 对复制树逐文件及目录同步。新 manifest/journal
  schema 2 校验会话、版本、序号、唯一身份、绑定和路径；schema 1
  不含 reset/恢复边界，拒绝当作 schema 2 读取。仅无换行的尾段视为
  截尾，修复失败可重试。重复、异会话或畸形的完整记录硬失败。
- 每次恢复先持久写入 restore-begin，再从创建或 fork 时保存的状态文件
  baseline 重建，绝不叠加到存活状态；reset 先持久写边界再清状态并写
  completion，旧 Pure cell 不会复活。中断 reset 在 reopen 时完成；中断
  restore 时执行受阻，重试从 baseline 重新开始。每次重放采用新的工件
  身份，残留工件不会占用下次序号。源码与两条完整输出流的长度和摘要
  均先核验（流式计算）；重放使用核验通过的同一源码字节。损坏项标为
  Corrupt，DeclaredEffect 只留回执不重放（A15），Unknown 待对账。
- state 文件的读取、重置和 baseline 恢复经 preopen 根目录 capability
  相对操作，不信任 guest 创建的祖先 symlink；持久 dispose 写入失败
  仍保持执行隔离并可重试。调用者提供的 enforced 标志会被归零，持久
  manifest 若伪称强制则拒绝。嵌入复制源树内的 fork 目标在创建前拒绝，
  使用外部 state mount 的 fork 不支持隔离而明确拒绝。
- 诚实失败语义：`cancel` 报告 NotInterruptible（preview1 无中断机制）；
  `install_dependencies` 报告 Unsupported，environment_generation 不伪造
  移动（R083 未实现安装器）；COW mount 由 `shenko-wasm` 拒绝；
  `ResourceLimits` 声明但不声称强制；recovery_level 固定 R0。

新永久测试按行为计 **9 个独立场景**（8 个 test 函数；下列最后一项
包含两个独立行为）：① cell 跨进程执行和显式流；② Pure/effect/Unknown
选择性恢复；③ reset 后恢复；④ effect 输出损坏；⑤ 重复 cell 准入拒绝；
⑥ guest 祖先 symlink 的 state confinement；⑦ extra mount 私有目录重叠
拒绝；⑧ 中断恢复后的执行隔离；⑨ 含孤儿工件的恢复重试。guest 是
合成 preview1 WAT，不是解释器交付证据；这些测试尚待主控运行。

仍缺（如实记录）：真实 CPython-WASI/Pyodide/Node/Bun 工件均未绑定
（无可用上游 WASM target 时具名条目保持 unavailable）；R1/R2 恢复
（对象/VM 状态）未实现，仅有 kernel 声明的 state-file 机制；包安装器
（R083 实装）、cell 超时/资源强制、interrupt、并发 cell 均未实现；
未接入 cordis Plugin 生命周期与 Store 任务记账（worker 绑定仍是
自由字段）。恢复只能重放调用方标为 Pure 的当前代 cell；effect 或未知
cell 的解释器状态不能从回执推导，Corrupt/NeedsReconciliation 必须由
调用方处理。单会话多 handle/多进程并发写入尚无锁；额外挂载仍由调用方
管理，底层 `shenko-wasm` 的预打开仍按路径重开，不能声称抵御其他宿主
进程在校验与 preopen 之间交换祖先的竞争。文件系统/平台 fsync 和断电
语义依赖实际宿主；这里没有物理断电证据。

建议主控串行验证：`cargo build --locked -p shenko-repl` 与
`cargo test --locked -p shenko-repl`，另用固定候选 SHA 的临时 consumer
覆盖：重复 recover 不累计；fork baseline 与嵌套目标拒绝；失效/foreign
manifest、journal 版本/序号和输出字节；截尾修复失败后原 handle 重试；
manifest 写失败后 dispose 重试；enforced=true 请求和持久 manifest；
replay 开始后在写工件/截尾时中断再恢复。检查目录及文件 fsync 的实际
执行路径，不能仅用普通重启冒充断电测试；另测实际可得解释器工件才可
主张该解释器交付。

## 本工作包的验收／交付
Node执行WASM不等于Node自身WASM；恢复不重复外部effect；依赖升级/中断/状态丢失的实际保证明确。

PR 附实际候选 SHA、输入版本、命令／交互与退出码、证据位置、失败／恢复／取消相关结果；fixture不能当真实环境，长期观察不能加速伪造。范围较大时可自主继续拆 focused 子 PR，并把接口和依赖回写本 issue，不设人工拆分审批。
