## 当前已具备与真实差距
kernel 使用真实 Cordis 原生合同；基线为 `1754062cef67cfc119fc7a2084c0321a231b9092`，
终止操作补丁从该固定提交向前追加并锁定，现有调用为：
`Supervisor::spawn<P: cordis_core::Plugin>(plugin, config)` → `Plugin::prepare` →
`PreparedPlugin::from_input` → `Context::spawn`。返回真实 `FiberHandle`，供
`Supervisor::restart(&fiber)` 进入同一 Fiber 的原生换代；`Context::provide<S: Service>`、
`InjectSpec`、`Context::run/effect/effect_sync` 建立实际依赖和 generation-owned 清理。
旧候选 ec5d446 的作者/提交和原现场保持不变；当前增量向前删除旧 Shenko Plugin trait、
meta/start/stop fallback、PluginContext/generation 计数、字符串 PluginService 和独立 ServiceRegistry，
不提供双路径或旧字段别名。所有仓库内旧接口调用者（两项 kernel 测试）已迁移，其他业务调用不冒充已接入。

Why：typed current-allocation removal 不是完整 Runtime 终止合同：它既不能封闭另一个
worker 的原生 attach，也不覆盖原生 Context 组合创建的其它类型，且已 detach 的旧 allocation
仍可处于 cleanup。固定原版 `1754062` 没有公开的全 resident shutdown API；本次向真实
Cordis fork 增补 `Context::close_plugins`（`cyjin-yl/cordis-rs@9a8a49fa459991ee29da73fb42ea9324cee9b680`，
workspace Cargo.toml/Cargo.lock 精确锁定），
不是在 Shenko 另造插件框架，也不冒称原版已有该 API。Registry 的 attach/close 共用同一
短锁，close 同时永久封闭所有 Context 的新 Fiber admission 并冻结 flat residents；
并行等待每个准确 cleanup/Disposed/unlink barrier，包含已 detach 的 allocation。
永久 root Fiber 及 root 注册仍保留，业务注册必须在 Plugin::apply 内。原生 caller-owned
pending spawn 仍须由其调用者完成或 drop；shutdown 不以超时伪报完成。

Shenko 删除异构 typed removal 清单，stop 直接调用这项真实原生 Runtime 终止操作。
取消 token 用于中断本层未完成 spawn，不再把一次 select cancellation poll 当 admission
线性化点。completion 使用 `Context::spawn_attributed` 保留原生 settle attribution；
普通 caller 取消只放弃等待，原生 cleanup 有完成承担者。回调内/并发 stop 立即返回
in-progress，不能把它当清理完成；稍后可再 stop 观察准确 barrier。run join/stop signal
按原生 LIFO 顺序组合，不恢复旧 meta/start/stop 或串行 lifecycle actor。

创建结果与宿主健康分开：一次已准入且成功的 spawn 必须交付真实 FiberHandle，不能因
另一 Fiber 的失败清理而转 Err 丢弃 handle。未知诊断仅闭锁后续 admission/restart；
stop 仍清理全部 resident，读取失败不清除 unknown。error Display/panic payload 的异常
销毁继续由 Cordis containment 承担。这不是 durable 对账，进程/机器丢失不证明外部效果撤销；
正常退出必须 await stop，任意 Runtime Drop 不冒充恢复完成。

本轮定向证据：kernel 现有三项测试继续运行，失败隔离测试补入“健康创建在途时其它 cleanup
设 unknown 后仍交付 handle”；只新增一项 native Context 组合→typed detach→取消原 removal
等待→stop 仍等待 child cleanup/run join 的真实场景。Cordis 只新增一项 Registry close 后
迟到 attach 拒绝且 detached resident 仍在冻结集的回归（本轮共两个新增测试函数）。
此前新测试因误用 `NativeChild` 而非 `Arc<NativeChild>` 的真实 TypeId 合同而 timeout，
以及误把 Unloading 服务视为仍可 lookup 而失败；均改正测试假设，原日志保留。
依赖首次8项gates有7项通过，test在300秒冷trybuild编译时timeout；106项core单测已通过。
续验发现旧 `Context::shutdown` 的compile-fail合同被新方法名意外恢复：保留该测试，
向前改为明确的 `Context::close_plugins`，在Cordis ADR0028记录真实需要触发的窄范围扩展，
不保留旧shutdown别名、不恢复root teardown。原失败日志保留，最终提交重验结果与精确
命令、退出码及日志在 PR #31/issue #8 checkpoint 更新；文档检查与代码证据分开。
这些是 kernel/库集成证据，不是 A18/H08 或完整 C03 验收通过。
