## 当前已具备与真实差距
kernel 的 `Supervisor::start/restart/stop` 现经 `PluginRegistry` 的串行 owner 进入固定 rev
`1754062cef67cfc119fc7a2084c0321a231b9092` 的真实 cordis：`PreparedPlugin` →
`Context::spawn` → `CordisAdapter::apply` → generation-owned `Context::effect`，
`FiberHandle::restart/dispose` 负责实际换代、清理和解除注册。旧 `meta/start/stop`
插件通过默认 `start_with_context` 桥接；新插件可在传入的真实 `Context` 上发布 typed Service
和登记 effects。`PluginContext.generation` 是本注册项的 apply 次数，不冒称上游未公开的 generation ID。

Why：生命周期操作由持有真实 FiberHandle 的独立 owner 串行推进，调用者放弃 oneshot 等待不会
丢失启动/清理责任；注册表短锁仅用于取得快照，不跨 await。新增批次失败只清理该批次，保留先前健康
Fiber。旧 stop/cleanup 返回错误或 panic 时闭锁后续启动/重启，读取错误不等于对账成功；所有剩余
清理仍被尝试。原生 effects 的失败按 cordis 自身的诊断合同报告，不能把 drain 完成或 Future Drop
当成外部效果已撤销。显式 stop 仍是正常退出义务；进程被杀、外部 Tokio runtime 退出以及任意未受管的
外部资源并无自动撤销保证。

定向证据：`cargo test -p shenko-kernel` 的两个新增
[`Supervisor` 集成测试](../../crates/shenko-kernel/tests/cordis_lifecycle.rs)
在真实 pinned cordis runtime 上通过：调用者取消后仍不重复启动、同一真实 FiberId 重启但 Service
publication occurrence 更换、停止后 Service/effect 解除注册；部分启动失败清理、旧健康 Fiber 保留、
未知 stop 不自动重启。它们是 kernel/库集成证据，不是 A18/H08 或完整 C03 验收通过。

**仍有生产装配缺口**：当前 `bin/shenko` 未创建/注册 Supervisor 插件图，直接构建业务服务。
本切片未改 main/subject/broker/SSH，不能声称默认业务闭包已由 cordis 托管。`ServiceRegistry`
和 `PluginService` 仍是旧 Shenko 接口，能力字符串尚未转成真实 `InjectSpec`，没有提供依赖闭包排序。
后续须装配默认业务插件、迁移 typed bindings，落实 §41.8 版本化 hook/schema/依赖图/冲突拒绝、
在途闭包租约和 §41.12 持久 activation/handoff。`restart` 是破坏性 Fiber 换代，不是原子发布热图。
本包列出的 A18/V1-15/E10/H01–H10/P41-04/07/08 都仍保留完整验收义务。

这是接续任务，不要求重写已有代码。未合入候选由主控发布可取的 checkpoint 后复用；若候选尚不可取，先推进接口、独立实现或相邻可做项，不等待原作者在线。代码路径及实际候选会随后写入任务清单。
