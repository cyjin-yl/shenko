## Why／目标

## 当前已具备与真实差距
BuildProvider 独立 worktree 已有；main 已有 NapCat durable ingress/S1 disposition ACK、
publication ledger 与有限 native child dispatcher，但尚无消费 seat 接口的 child handler。

### 2026-10-29：本地 TaskSeat 生命周期与 writer lease 接口

从实际 main `5959e455af637fd1edd55fbeb2e94af725131b74` 接续，复用现有 Store mutation line、
SQLite IMMEDIATE 事务与 commit_log，不重写 NapCat ingress（#101）或 native child 框架。
`shenko_store::seat` 新增持久 SeatRecord、SeatLocation、SeatLease：任务可按稳定 seat ID
找回位置，位置移动产生 supersedes 后继并保留旧记录，退役／迁移终止旧 lease；新的 writer
取得 lease 时原 lease 在同事务失效。SQLite partial UNIQUE index 限制每个 seat 最多一个
current lease。`check_seat_write` 在一个读事务里核对 holder、seat 存活与 incarnation，
返回 typed Seat ProtocolError；human takeover 可由真实观察者明确结束 lease。
pane lookup 同时使用 host 与 pane_id，不把跨主机同名 pane 混为一处。

这是已实现的可信 runtime 接口，不是完整 QQ→main→child→seat 闭环：没有新业务分派、
管理员 gate、model 控制标签或自动输入。调用方仍须核验真实 task/controller 委派；任意
UUID 本身不证明权限。主 runtime 尚无 seat-child handler 来调用它，当前 TmuxSeat 不受
此接口自动围栏；成功读取 lease 不构成原子 check-and-send，也不能围栏原生人类输入。
这些记录是本地运行事实，尚未加入 cognition replication／升级 handoff 水位；跨节点不得
把它们当作已转移的写入权。C07 的 exec-side verified-send 是独立相邻切片。

### 2026-10-29 复审修正：准入不变量与可恢复 lease

按独立 review 修正同一接口，不移除既有事实：
- 每个 (host, pane_id) 至多一个 active seat 改为提交内原子执行：`register_seat` 与
  `relocate_seat` 在同一 IMMEDIATE 事务里核对占用，`idx_seat_active_location` partial
  UNIQUE index 由 SQLite 兜底；重复认领返回 typed `seat_location_occupied` 并指明
  incumbent，`seat_at_pane` 仍为纯查询。relocate 可在同一事务里退役自己的前任记录并
  接续同一物理 pane，但不能顶替另一 active seat。
- `acquire_seat_lease` 改用调用方在尝试前选定的 `lease_id`：同一身份重放直接返回已存
  lease（即使已被取代），崩溃或 commit 结果不明后可无歧义找回，不会顶掉更新的合法
  writer；不同 seat/holder 复用同一 lease_id 以事实不符报错。调用方须在尝试前持久保存
  身份，恢复时查询／重放原身份，而不是生成新身份把重试伪装成新的 takeover。
- `relocate_seat` 校验前任 seat 的 task 绑定，绝不把 A 的工作位搬给 B。
- `end_seat_lease` 只接受新枚举 `SeatLeaseEnd`（`Released`/`HumanTakeover`）；
  `Superseded`/`SeatSuperseded`/`SeatRetired` 只能由 acquire/relocate/retire 在产生该
  变迁的同一 commit 内记录，公共入口无法在缺变迁的情况下写入这些原因。
- `seat_successor` 用访问集合检测环，任意长度的合法搬迁链都能解析，不再设 64 上限。
- `check_seat_write` 的 `seat_lease_ended` details 中 `reason` 为 `LeaseEndReason` 的真实
  JSON 值（可直接反序列化），不再把枚举先转成 JSON 文本再包一层字符串。已有落盘
  `seat_leases.end_reason` 列格式未改变，完整 lease JSON 仍是读取来源。

整个增量相对 `5959e455` 保留 **5 个测试、9 个独立永久情境**（原 4 个加修正 5 个），
没有通过提交／helper／循环分摊额度：
1. writer 替换使旧 lease 失效。
2. Store 重开保留当前／已结束 lease。
3. human takeover 拒旧写入；同一路径直接反序列化 error 的 `reason` 值。
4. 正常搬迁保留 task／历史并终止旧 location lease。
5. 两个 Store discoverer 都读到空 pane 后，第二个注册仍被提交内占用检查拒绝。
6. relocate 进入另一 active seat 的 pane 被拒，前任及其 lease 不受影响。
7. 重开后重放原 acquisition 身份返回已被取代的 lease，不顶掉更新 writer。
8. relocate 使用不同 task 被拒，原 task 的位置／lease 不受影响。
9. 单条包含 69 次搬迁的历史可从原 seat 解析到末尾；不是 69 个独立参数化情境。

公共 end reason 的非法生命周期说法由 `SeatLeaseEnd` 类型排除。已删去重复的当前 lease
重放、退休后复用 pane、错误 task 后再正常 relocate 等额外情境；不另写兼容路径或隐藏
case。索引创建会拒绝已含多重 active pane 认领的旧本地库，不自动选赢家或删除事实；
这种先前损坏的数据需显式调和后再打开。

对应正式 case 仍为 A27、A28、V1-01、V1-05、V1-06；本次只推进其 seat task 连续性接口，
不声明任何完整 case 通过。未运行任何构建、测试、formatter、服务、QQ、网络或模型调用，
因此编译与运行结果均未建立。

交父级在受管开发容器／shared heavy-work guard 下串行验证：
`cargo test --locked -p shenko-store --test seat_lifecycle`，随后
`cargo test --locked -p shenko-store`。建议独立 consumer 以真实 Store 重开后读回 supersedes
与 lease 状态；并发双 handle 竞争注册／relocate、丢弃 acquisition 返回值后重开重放、
同 pane 接续和损坏库 cycle 检测由父级作 native smoke。永久回归没有注入 commit 失败或
物理断电，也没有新增破坏库 fixture。这些确定性检查只证明本地机制，不证明模型路由、
真实 TUI、QQ 或升级成功。

这是接续任务，不要求重写已有代码。未合入候选由主控发布可取的 checkpoint 后复用；若候选尚不可取，先推进接口、独立实现或相邻可做项，不等待原作者在线。代码路径及实际候选会随后写入任务清单。
