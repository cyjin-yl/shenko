### NapCat 高位无符号 ID：新接收及旧弱记录匹配

- 新接收的非零 OneBot 整数 `message_id` 覆盖有符号范围及 `i64::MAX + 1..=u64::MAX`；与其完全相同的规范十进制字符串沿用原有身份等价规则。已有负数、字符串、零、浮点数以及缺失身份字段的规则不变；账号仍由接收库 cursor 绑定，conversation 使用原有带类型的身份。
- v1/v2 保留原 schema version 和原有 v1→v2 迁移分组语义。新增 SQLite 表达式索引只索引持久 JSON 中的整数 token，不重写事件、source key、seq、eligibility、已确认处置或原观察。对新到达的高位无符号整数或等价字符串，已有强来源仍优先沿用原观察路由；没有强来源时，按完整身份核对索引候选，若匹配历史弱记录，仅向该真实旧来源追加相应 replay／冲突／修订观察，不生成另一条待投递事件；均未匹配时按强身份接收。主控对锁定的 bundled SQLite 3.46.0 实测：`->` 保留 `9223372036854775808` 与 `18446744073709551615` 的精确文本，等值查询使用表达式索引；`json_extract` 将这两个值当作 REAL，不能用其数值作身份。探针回执：`build/c13-sqlite-identity-20261029/receipt-17d1daf1.json`；该探针不等于本候选完整行为验收。
- 这**不对账或隔离已经存在的重复事件**：旧弱重复若原本可投递，仍然可投递；无论已打开还是之后启动的旧 v2 writer 都仍能写入新的弱重复，升级不能声称已 fencing 旧 writer。首次打开需在初始化事务中建立索引并读取既有历史；大库建索引耗时及与旧 writer 的锁争用尚未测量。已发布的 draft v3 结构不同，本切片在变更 journal 或创建索引之前明确拒绝该版本；保留原库及 WAL，用支持其格式的恢复工具处理，绝不按 v2 猜测。它不是完整 #18、真实 QQ 验收或旧重复恢复的证明；此候选的测试与运行结果由主控另行记录。
