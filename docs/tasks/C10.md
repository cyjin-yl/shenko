## awareness 已接入主体（2026-10-27）

此前 `AwarenessRegistry` 只有库与测试，没有任何生产调用者：觉察写下来也到不了模型。
现在主应用启动时装载内置种子与 `data_dir/awareness/*/AWARENESS.md`，每个 subject 步骤
用该步真实输入检索单元，并把命中的正文作为**易变的每步后缀**追加在稳定前缀（合同＋
人格）之后，明确写成"提供一种视角，不是必须执行的命令；可以采纳、改写或忽略"。稳定
前缀保持在前且是 context profile digest 的输入，因此每步不同的觉察不会反复更换 KV
窗口。停用的单元根本不注入；注入不触发任何分支，也不授予权限。

取用改为**有界全量注入**（合计默认 4 KiB，超出预算只列 id 与能力卡）。此前试过两个
方向的关键词检索，沙箱实测都失败：先看"提示词里的词是否出现在单元 id/卡片里"，真实
消息（"什么 都打不开了"）命不中；改成"单元自己的词是否出现在消息里"后仍然命不中
"网络"这个从未出现的概念词，导致单元没被注入、启用与停用结果几乎一样。按关键词检索
等于在最需要视角时把它藏起来，所以现在不做词匹配，选择交给模型。

单元只提供原则与视角，不写具体动作：写死步骤只在那几个处境里有效，还会让评测退化成
背台词。通用性、是否有效由真实沙箱的成效自测回答，方法与防作弊要求见
[内核零业务，能力优先写成 perception + awareness](../development/awareness-first-plugins.md)；
不得用禁用词/步骤词正则表代替判断。首轮实测数字、失败原文与未证明范围见
[local-model-and-awareness 证据](../evidence/local-model-and-awareness-20261027.json)。

这是接续任务，不要求重写已有代码。未合入候选由主控发布可取的 checkpoint 后复用；若候选尚不可取，先推进接口、独立实现或相邻可做项，不等待原作者在线。代码路径及实际候选会随后写入任务清单。
