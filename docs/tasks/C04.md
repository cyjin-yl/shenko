### 2026-10-25 原生 Text/Image wire 切片

- 从实际 main `3e3ca0a8320499cee775aaf94bbe8ce30441a13e` 接续。`InferenceMessage` 只保留有序 `parts: Vec<InferencePart>`；Text 与持有 `Arc<[u8]>` 的 Image 共用同一原生表示，已移除 `content: String`，所有生产构造、纠错和恢复断言一并迁移。Anthropic 发 base64 image source；OpenAI-compatible 发 data URL，均保留混合 parts 次序，base64 字符串直接移入 JSON，避免额外的大块复制。
- 两个 provider 的 serializer revision 均为 3；冻结 S0 schema／CAS codec 均为 7，Store 的 identity admission 也严格接受 7。旧 seal 明确阻断恢复，不引入 String/list 双表示或旧版本 fallback。冻结 binding、reserved native options、Anthropic 采样限制与 unknown／never-dispatched 记账不变。
- 现有 broker 2 项测试通过；迁移 Store 校验后，`cargo test --locked -p shenko-store -p shenko-subject -p shenko --lib --tests -j1` 的 24 项现有测试通过，包含身份替换／S1 崩溃恢复与真实 native 子进程重开。首轮因漏迁 Store 的版本判断而有 2 项身份测试失败；修复校验入口，不放宽约束或改写测试预期。没有增加只验证 serde／复制／JSON wiring 的永久测试。
- 独立、唯一 package 名的真实 Rust consumer 先持久化／重读原生 payload，再通过两条 provider HTTP 路径向真实 Qwen 视觉端点发送 Text/Image/Text。720×200 PNG 的 SHA-256 为 `e8549fc2190bb04aee68b6838e151359e1c10263484d2f36067a76812f91de32`；两个协议都返回图中六位数字 `271828`，分别以 `stop`／`end_turn` 正常结束。OpenAI broker 还实际拒绝不支持 MIME 和空图片，结果为 `InvalidRequest(InvalidImagePart)`／`NeverDispatched`，active count 为 0。此证据不是仅检查 serializer JSON 或 mock 回显。
- 证据在 `doescontainer` → `shenko-dev-live`：OpenAI 为 `/tmp/shenko-native-image-wire-sy56yyxz/result.json`；最终 Anthropic 为 `/tmp/shenko-native-anthropic-image-v2-25iunrtf/result.json`，完整响应为同目录 `response.json`。首轮 Anthropic 在 1024 输出上限下返回空文本，原始响应未被该版 probe 保存，不计通过；修正 caller 先保存完整响应后，以 4096 上限发出的新请求通过，不把首轮重记为成功。最终 tracked Rust/Cargo 输入摘要为 `e385091c36df56b351fd63ed86a6ce6a10aba49c26f73a76a12e1466ae7de045`，按排序路径＋NUL＋bytes＋NUL 计算；与 OpenAI 取证输入仅差 Store 的 schema 判断，broker/types 输入逐项相同。
- 范围为 PV01／PV02 的原生消息形状、冻结绑定与真实图片传输子路径，不据此通过完整 case。真实响应只提供总 input/output tokens，cache/image 明细仍 unknown；不从文字 context 推断视觉额度，不把 Qwen 的 Anthropic-protocol adapter 冒称真实 Claude 验收，也不升级为四流 128K／KV／视觉精度全量证据。正式 C20 projection→thought-loop 接线仍继续。
