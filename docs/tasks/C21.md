Linux/Android 使用 rustix 的 `renameat_with(NOREPLACE)`，Darwin 使用其 `RENAME_EXCL` 对应实现，Windows 使用 `MoveFileW`（不传覆盖或复制回退标志）；其他未确认平台显式返回 unsupported，不退回普通 rename。操作系统、内核和目标文件系统均须实际支持该原语；NFS 等远程文件系统中，rename 报错不能证明服务端未完成，因此必须检查 stage 与最终路径后再对账，不能盲删或盲重试。Windows 文档未在此确立目录移动的并发可见性保证，Darwin 文件系统能力、重解析点及各实际挂载行为也需另行验证；单次发布不是断电持久性承诺。

### 本次接入：本地启动所有权与主体轮次边界（不是代际激活）

`shenko start` 现在先取得同一数据目录内 `runtime-owner.sqlite` 的 SQLite 排他写者保留锁，再建立 genesis、dispatcher 或主体；锁一直持有到 Tokio runtime 结束，以免停止等待被误认成已终止在途工作。第二个配合此实现、访问同一锁文件的 `start` 被拒，进程退出由 SQLite/OS 释放锁；不得删除或替换活跃锁文件。该约束依赖实际 SQLite VFS/文件系统锁语义，未证明远程文件系统、跨机、容器不共享锁文件、旧二进制、直接库调用或独立 A/B 副本的单活。Node、Check、Sync 和独立 ingress 不是主体启动者，不因这一锁而停止。

`shenko --data-dir DIR runtime pause [--request-id UUID]` 在真实 Store 里提交一个绑定当时主体 generation/epoch 的请求，打印稳定 request ID；`runtime status UUID` 读取结果，`runtime resume UUID` 取消尚未采纳的请求或恢复**同一**控制者。主体仅在已登记的下一步为 `Planned`、无 active request/attempt 时将 head 与请求同事务变为 `Paused`；已冻结、推理中或已记录结果的步不被丢弃或重发。运行中的主体停在该边界，重开仍可读到暂停状态；恢复保留原 next step 和 epoch。无模型的确定性 runtime 没有主体 loop，因此新的 pause 请求不会自行抵达边界。请求和暂停是本机控制状态，不代表 B 已就绪，也没有自动升级路径会在 B 未验证时触发它。

边界回执 `boundary_at` 是本地 ledger 上该提交的有序坐标，不是 §41.12 的最终迁移水位：其后独立 ingress、Node 同步、已准许的 invocation/operation 和迟到 E1 仍可能产生事实；pause 只阻止新的主体步及新 native/QQ claim，已经 claim 的调用仍可能在边界后 arm/send。不会因暂停而释放、重发或清除任何未知效果，也没有从此回执推断外部端已停止。恢复同一控制者不增加 epoch，更不是切换或回滚 generation。内存 UI 输入和独立 ingress 的接续仍需各自可靠游标，现有内存消息队列不是交接证据。

Cognition archive 尚不携带这个本地控制记录；若 head 已暂停，生成快照会在一致事务内拒绝，而不是复制一个无法恢复的 paused head 后声称可恢复。恢复活动状态后可继续导出；完整 SQLite 副本保留本地记录。此措施不完成跨版本 archive schema、跨节点 fencing 或两副本交接。当前 `shenko-update::advance` 仍仅更改内存中的阶段提议，不能作为持久 ActivationRecord、B readiness、handoff、observe 或 rollback 成功证据。

完成 #26/A39 仍需共同的持久 ActivationSelector/恢复闭包、候选真实有限 smoke、可对账的完整 w0→w1 增量及 cursor、跨代原有 invocation/E1 通道、实际新 epoch/路由/服务切换，以及 B 新事实回退时的 reader/importer；当前代码不应把独立副本分别当作可启动生产控制域。未执行本增量的测试、构建或原生 sandbox；具体适用的 A21/A39/V1-07/V1-08/E06/DX12–16/RT12–13/P41-10–11 仍未据此标为完成。
