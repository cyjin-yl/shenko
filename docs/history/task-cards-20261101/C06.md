### 2026-10-30 切片（分支 feat/c06-named-wasm-20261029）

通用 named-tool 安装/执行通路已落地（源码层，未跑构建/测试），并已按
评审以 canonical unit authority 重写：

- **工具=节点单元**：工具就是 `UnitKind::Code` 单元（unit_id `tool.<name>`，
  revision=version，`config.tool` 描述符），经 `UnitRequest::Import` 导入，
  工件字节进 CAS/objects 表，`<data>/tools/` 仅是 package_root materialization。
  删除了第二注册表（原 ToolStore/tools.json）。
- **真实 ABI 检查**：`inspect_module` 对字节做 `Module::new` + linker 签名
  比对（`_start` 为 `()->()`、`memory` 导出、全部 import 属于
  `wasi_snapshot_preview1`），component 模型识别为 `WasiComponent` 并拒绝。
- **真实执行**：`wasi.exec` handler 每次运行都读本 installation 的
  node DB 单元事实并用 digest 重新取字节、重查 ABI；guest 在真实 C05
  `WasiRunControl::deadline` 下跑，spawn_blocking 线程永远 join 后才清理
  io 目录；stdout/stderr 全量 `cas.seal_reader` 进 CAS，normalized 只放
  ≤16KiB utf8 preview + `ObjectRef`。EffectStatus 仅在全 ReadOnly mount
  且有真实 terminal outcome 时为 None，否则 Unknown。v2 输入可显式选
  `mount_profile:"read_only"`，实际撤销写权限且完整闭包冻结进 T1 和 worker；
  这部分可走既有 T2。默认 RW 仍不结清、不自动重放，完整 C06 继续 open。
- **CLI 绑定**：`tool exec` 先 `bootstrap::validate_home_for_exec`（manifest
  + mount source 规范化 + runtime/gen/ready 标记）、既有 ledger/subject 的
  只读 identity projection（复制 db+-journal/-wal 到临时快照后读——原始
  元组零写入且 WAL 感知，撕裂/持续变更如实拒绝），再 `Node::open_inspect`
  （只读、不产生恢复 mutations）；`tool list` 永不创建 store。
  `tool exec --read-only` 采用与 native 同一显式降权规则。
- **toybox 真实移植工件**：`crates/shenko-wasm/ports/toybox-wasi/`
  （wasi-compat.h + 7 个对 0.8.15 实源的 #ifdef 补丁、额外生成文件封存补丁 + miniconfig +
  single.sh 构建脚本 + ACQUISITION/SMOKE）。需外部 wasi-sdk-34 与 host cc
  实际产出 .wasm；未产出前该具名目标保持 unresolved。

A09 的 Git/SSH 端到端认证未达成，全部具名目标保持 unresolved，不勾完成。
