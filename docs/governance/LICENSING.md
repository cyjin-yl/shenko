# Shenko 许可提案（PROPOSED，尚未生效）

状态：**提案**。本文件记录 owner 的方向与待确认事项，不改变当前仓库的授权状态，也不替代正式 LICENSE 文件。

## 目标

1. 社区版 Shenko 持续开源，避免把公共贡献变成闭源竞争产品或只对付费托管服务开放的衍生品。
2. owner **本人 `cyjin-yl`** 保留闭源、商用及另行商业双许可的权利。
3. 贡献者保留原作者身份与 Git 提交归属；授权边界清晰，不用 DCO 冒充商业授权，也不把第三方代码据为己有。

## 建议方案

- **社区主许可：AGPL-3.0-or-later**。
- **owner 个人商业双许可**：由贡献者对其有权贡献的 Shenko 部分，向 `cyjin-yl` 授予非独占再许可（见 `CONTRIBUTOR_LICENSE.md`）。
- **DCO**：只证明贡献来源与提交权，不自动授予 owner 闭源或商业再许可权（见 `DCO.md`）。

AGPL 比 GPL 更适合 agent/服务部署：公开网络服务的使用者也应能获得对应修改后的源码。它不禁止企业内部私有使用，也不阻止法律允许的其他使用；若目标是连内部私用都禁止，应讨论 source-available 商业条款，而不是把该条款伪装成 OSI 开源许可。

选择 `or-later` 便于未来评估许可证升级；若更重视版本确定性，可改为 `AGPL-3.0-only`，需在采用前明确记录。

## 权利边界

- owner 的再许可主体是 **`cyjin-yl` 本人**，不默认转移给未来公司、基金会或任何 agent。
- 贡献者只授权其实际有权提交的 Shenko 部分；第三方依赖仍按各自许可证处理。
- `cordis-rs` 已核实为 **MIT**，不得因 Shenko 选择 AGPL 而改写上游许可。
- `Cargo.toml` 当前的 `Apache-2.0` 元数据不等于社区已完成许可选择；仓库此前缺少完整 LICENSE 正文，需正式采用时补齐并记录变更。
- 未经贡献者明确确认的既有贡献，不自动视为已获得商业再许可。未确认前仅按原有事实保留历史与署名，不据此宣称已取得闭源授权。
